# MiniMax H3 剧本拆分与分镜工作台方案 v1.1

状态：v1.0 已交付单集闭环；v1.1 已交付整本多集、本地优先的自动识别与一键生成。范围：本地工作台、单一 MiniMax H3 输出，不含 Seedance 或自动发布。

## 1. 目标与交付契约

把短剧原剧本拆成连续的 15 秒段，先形成可编辑的导演构思，再生成可审阅的分镜脚本与逐段可复制的 H3 提示词。每段最多使用 6 张参考图作为**文字描述来源**；最终正文写具体视觉事实，不用图号或“见参考图”代替描述。同一张图的固定描述跨镜、跨段保持一致。

固定契约：三种创作模式（文戏、武戏、综合）；每段目标时长 15 秒；每镜标题含时长，正文固定 14 条；一段内各镜时长合计 15 秒；文戏与武戏专项规则分开编译。

```text
导入原剧本 → 拆场与剧情节拍 → 参考图描述定稿 → 规划15秒段
→ 导演板设计 → 逐段选择文戏/武戏规则 → 14条分镜正文
→ 编译H3复制稿 → 连续性校验 → 导出与版本归档
```

## 2. 工作区与数据流

| 工作区 | 操作 | 保存结果 |
|---|---|---|
| 剧本 | 导入、校正场次与说话人，标记原台词、动作、关系转折、关键道具 | 不可覆盖的原稿版本；场次与节拍清单，逐项关联原文位置 |
| 视觉资产 | 导入图片、区分人物/场景/道具，识别后人工修订和确认 | 图片原件、来源哈希、描述正本及版本 |
| 导演板 | 规划15秒段、俯视站位、轴线、镜头、表演、光色、声音和衔接 | 可编辑、可锁定的场/段/镜导演决定 |
| H3交付 | 按模式编译、对照原文、检查与导出 | 14条分镜脚本、逐段H3复制稿；质检结果留在工作台内部 |

主界面以“原剧本 / 导演板 / H3成品及问题清单”三栏为主。点击镜头可反查原文、视觉描述版本及其导演依据。局部修改只重算受影响的段落及相邻衔接，不重新编造已锁定的设定。

层级：作品 → 集 → 场 → 15秒段（P）→ 镜头（SC）。镜头编号在同一集连续；段落保留自己的起止状态与原文范围。

## 3. 文戏、武戏、综合

| 模式 | 规划重点 | H3编译规则 |
|---|---|---|
| 文戏 | 台词容量、人物关系变化、固定声线、微表演与倾听反应 | 文戏范式 D；15秒常态约36–44字有效台词，48字为硬上限，复杂动作/迟疑需降低容量；通常3–5镜 |
| 武戏 | 阵型、攻防因果、武器和能力依据、空间动线、环境物理反馈与胜负落点 | 武戏范式 E；15秒动作阶段，默认不编造对白、武器或超自然能力 |
| 综合 | 一集内逐段标记文戏或武戏，检查类型切换处的状态交接 | 每段只调用其所属类型的规则，不建立第三套混合模板 |

可设置整集默认模式，并逐段改选。某一段同时包含大量对白和高密度打斗时，提示在关系或行动转折处拆段，不能把两套专项格式塞进同一条提示词。改选类型不修改原稿和视觉描述正本。

## 4. 15秒分段与导演构思

按“承接/钩子 → 触发 → 推进与反应 → 信息或关系落点 → 末帧交棒”切段，不按台词行等分。每段只承载一条主要动作链和一次明确的关系变化。换场、绑定人物改变、动作结果或关系不可逆转时优先设为边界。台词和动作超载则拆段；不足15秒时用有叙事信息的观察、迟疑或环境反应承接，不空转、不强行加速台词。

场级先确定戏剧目的、俯视站位、人物相互距离、180度轴线、主光源与环境声音。段级确定原文范围、起止状态、使用的视觉描述版本、台词预算与时间分配。镜头级确定构图、焦距/机位/运镜、动作与环境接触、微表情、光色、声音及衔接。多人互动和关键道具落位先确认空间；允许人工锁定决定，重生成不得覆盖锁定项。

导演板必须回答“这镜为何这样拍、观众得到什么信息、下一镜如何接”；单纯炫技或抽象情绪词标为复核项。

## 5. 参考图描述正本与一致性

每个 15 秒段最多选用 6 张参考图作为描述来源，计数按**不同图片文件**，不是按字段或引用次数。此数字是工作台的输入约束，不宣称是 H3 平台上限。图片原件只在资产区供核验；导出提示词不用 `<Picture 1>`、`@图片1` 或“参照上传图”代替视觉描述。参考图可选，缺图时允许使用人工确认的文字设定并标清来源。

**资产是项目级的（2026-10-05 起）**：参考图导入一次即进**全本资产库**，不隶属任何一集；各集生成时按该集的说话人名册、场次名册与剧情自动选配到段（同一张图可被多集各自绑定）。匹配结论是「集 × 资产」的关系，逐集记账、互不覆盖——故同一张主角图在 A 集可能判为高置信度、在 B 集判为中置信度待复核，两者并存而非互相覆盖。「未绑定」只在「本集匹配过它却没绑上任何段」时才算待处理项。

| 资产 | 固定锚点（跨段复用） | 可变状态（按剧情事件更新） |
|---|---|---|
| 人物 | 面部辨识特征、发型、体型、当前造型、固定配饰 | 表情、姿态、站位、持物手、伤痕、服装沾染 |
| 场景 | 门窗/家具方位、层次、材质、固定光源、空间轴线 | 门开合、灯状态、烟尘、破坏、天气作用 |
| 道具 | 外形、颜色、材质、固有痕迹 | 持有人、落点、开合、损坏、接触关系 |

一张图只识别和确认一次；正本保存文件路径、SHA-256、描述、证据、人工修订、版本与使用位置。同图跨镜、跨段取同一版精炼固定锚点，不每次自由改写；变化只能写为有来源的剧情状态。造型或场景基线改变须建立新版本/新状态，并列出受影响的段落。历史导出保留原描述快照以便复现和回滚。

图片之间或图片与剧本冲突（如服色、门位、装备）时显示事实和影响范围，等待人工裁决；用户明确设定、图片可见事实和原剧本之间的取舍必须留痕，不暗中混合。仅文字描述能约束设定，不能保证 H3 视频像素级一致；生成结果还需人工验收。

## 6. 逐镜正文：标题时长 + 14 条

这是本工作台对仓库既有“标题时长 + 正文12字段”规则的**扩展格式**：前置两条已确认参考图的文字描述，其余12条保持原先相对顺序；不修改仓库规则正本。每个 SC 都保留全部14条；时长只在标题行，SC时长合计等于所在P段的15秒。

```text
P03｜15秒｜文戏｜她发现信封被拆过

SC07【推门停步｜4s】
① 人物参考图的描述：黑色齐肩直发，左眼下一颗小痣，穿深灰短款外套的年轻女子。
② 场景参考图的描述：书房入口在南侧，深色木书桌靠北墙，右侧窄窗引入冷色自然光。
③ 景别：中景。
④ 构图：门框占左前景，人物处于中景左三分之一，书桌位于右后景。
⑤ 焦距：50mm。
⑥ 运镜：从门内侧克制地前移，跟住她停步后的视线。
⑦ 光源：右侧窗光照亮桌面，人物脸部留少量阴影。
⑧ 氛围：门外走廊声远去，房内安静，视觉重心转向信封。
⑨ 人物站位 + 朝向：她停在南侧入口内，身体朝北侧书桌。
⑩ 肢体动作（方位/动线）：右手仍按门把，目光从桌面移到信封封口。
⑪ 微表情：视线停顿、下颌微收，一次压住的吸气；不预先露出完整惊讶表情。
⑫ 台词 / 内心OS / 旁白：按原稿类型标注并逐字保留；对白标注说话人，内心 OS 与旁白分别注明类型。没有内容时写“无”。
⑬ 音效：门轴轻响，纸张被风掀动一角。
⑭ 衔接：她的视线落到桌面右前角；接SC08信封封口近景，保持桌面方位。

SC08【触及封口｜6s】
①—⑭ 按同一顺序逐条填写；①②复用已确认的固定描述，动作和道具状态另写。

SC09【门外脚步｜5s】
①—⑭ 按同一顺序逐条填写；末帧记录人物、门、信封与声音状态，交接P04。
```

上例的SC08/SC09为**格式说明中的省略示意**，不是可交付成品；真实导出不允许合并行或缺项。无人物镜头仍保留①并写“本镜无人物”；无场景参考图时②写经确认的文字场景设定并注明“文字设定”，不虚构图源。道具图的事实融入④、⑩等实际画面字段，不另增第15条。⑭须写明动势、视线/轴线、声音桥接、节奏或情绪的交棒方式及下一镜/段，不可只写“切”。

## 7. H3复制稿与交付

14条分镜稿是可审阅的导演正本。H3复制稿由同一份结构化导演数据编译：文戏使用角色、声线与对白纪律，武戏使用攻防、装备与逐秒动作纪律。两者共用已确认的文字视觉设定，不各自重新识图或改站位。H3专属标签、固定尾部等若与14条展示格式冲突，只在单独复制稿中编排，不改变分镜正本的字段顺序。最终提示词仍需以具体文字描述视觉事实，不用图号占位。

导出按作品/集/版本提供：TXT 或 Word 格式的14条分镜脚本、P01/P02等逐段复制稿和来源与版本清单。质检在导出前执行，结果留在工作台问题面板与内部快照中，不写入 TXT/Word 分镜成品。原文定位、图像路径、内部版本号、校验警告位于复制区外。草稿、正本、导出副本分开存放，不自动同步或发布。

导出闸门按**集**判定：当前集无阻断即可直接导出，其余集的阻断不拖累本集；当前集存在阻断时，导出按钮仍可点击，由「全书阻断清单」列出全书阻断项（集号 / 段 / 镜 / 分类）并可逐条跳转定位，清单中可直接导出其余无阻断的集。导出按钮不得因任一条问题永久失效。

## 8. 校验与阻断规则

**阻断导出（事实类与内容安全）**。只拦事实问题与内容安全，不拦截人工确认状态或风格建议：

| 分类 | 触发项 |
|---|---|
| 输入不完整 | 没有可交付段落；段或各镜时长之和不等于 15 秒；单镜超过 12 秒；SC 编号断号；段落编号不连续；14 条缺项；缺少镜头导演意图；人物固定特征与人物状态缺失；⑭ 衔接只写“切”；台词超过 48 字硬上限；本段超过 6 张不同参考图；场次引用无效或跨场；镜头节拍映射遗漏、重复或乱序 |
| 原图描述缺失 | 人物固定锚点与人物参考图描述均未提供；引用的图片不存在或描述为空（空描述不会进入 ①②④） |
| 剧本结构 / 台词不一致 | 原稿版本引用不存在；场次或节拍与原稿不一致；原台词、说话人、顺序或原文位置被修改或遗漏；节拍遗漏、重复或乱序；相邻段落已确认的人物固定描述漂移 |
| 内容安全 | 正文以图号或“见参考图”代替具体描述；⑭ 衔接命中转场禁词表 |

**建议复核（不阻断导出）**：导演决策尚未人工确认；镜头过密；15秒对白与动作负载过高；武戏装备、能力与攻防因果；相邻镜段的站位、构图、光源、人物连续性；低置信度匹配与已入库未绑定图片；分集结果未经人工核对。综合模式须检查类型切换点。相同输入和确认版本重复导出，段数、固定描述、字段顺序与质检结果应一致。

分级口径为**单源闸门表**（`src/platforms/minimax-h3/validator.ts` 的 `issuePolicy`）：severity 与分类只由该表决定，调用点不得单独指定；新增闸门必须先登记，未登记编号无法通过类型检查。

生成后人工验收画面：对照人物/场景固定锚点，检查道具和站位连续性、口型与台词、声音、动作可读性；回填结果与问题，不用模型自述替代画面证据。

## 9. 实施阶段与验收样例

1. **闭环原型**：单集导入、三模式选择、视觉描述确认、15秒拆段、14条导演板、逐段H3导出、基础测试。
2. **连续性增强**：俯视空间图、复杂武戏、跨段状态账本、图源冲突裁决和版本影响分析。
3. **生产验收**：生成结果回填、画面一致性人工复核、批量修订与整集交付包。

首期验收用一集包含双人对话、文转武、换场、同一道具跨段、两张人物图和一张场景图的样例。检查15秒时长、每段最多6图、同图描述不漂移、SC的14字段、原台词保护、P段末帧接续，并在相同输入下重复导出两次比较结果。

本地数据以作品/集/场/P段/SC镜头组织；视觉原件、描述版本、原稿与导出副本独立管理。`E:\仓库`仅作为只读规则来源，不纳入本项目的写入、同步或发布范围。开发改动须同步索引与测试，每次完成后单独提交Git。

## 11. v1.1 升级增量（2026-09-30）

v1.0 的单集闭环之上，v1.1 补齐四项能力缺口，并把架构改为**本地优先、AI 可选**。需求与实施基线见 `9.30升级方案.md`，本节只登记已落地的契约增量。

1. **一本多集**：项目为「一本一个项目、内含多集」，数据模型 `schemaVersion` 1→2。分集识别支持 `第N集` / `第N话` / `EP0N` / `Episode 0N`；识别不到集标时整本作单集并显式告警，绝不静默硬切；切分后输出集清单（集号 / 标题 / 字数 / 场次 / 切点行号）供人工核对并可修正。v1.0 单集快照自动迁移为 v1.1 结构，旧存档不失效。
2. **批量导入与自动匹配**：参考图导入不设数量上限，且**导入即入全本资产库**（项目级单源，换集不必重导）；每段 6 张是**绑定**上限，超限时显式提示「已入库未绑定」，不再静默丢弃。匹配按三级置信度处理：高（唯一命中场景或角色）自动绑定、中（命中多个候选）标黄待人工复核、低（主体未命中）进入未分配区；道具图不自动匹配。匹配逐集独立，结论记在集上（`episode.imageMatches`），同图在不同集可有不同判定且互不覆盖。
3. **本地优先与一键生成**：本地引擎 A 做图像分析（图类 / 主体 / 主色影调 / 光源方向），本地引擎 B 做规则导演（节拍分类 / 镜头模板 / 构图 / 连续性继承 / 合规衔接生成，禁词本地拦截）。一键生成为单一动作，只填充 ③④⑤⑥⑦⑧⑨⑩⑪⑬⑭ 十一条；①②⑫ 由既有链路注入，任何生成方式不得改写。每条 SC 分镜固定 15 秒，生成幂等，只补空白、不覆盖人工内容（需覆盖须显式勾选），生成后该段 `confirmed = false`。
4. **AI 可选增强**：接口配置入口上移至顶栏，未导入剧本时同样可见，并附「测试连接」。默认关闭；开启后获得图片外观描述、剧情语义分镜与字段起草。AI 输出必须通过本地校验，未通过即自动回退本地结果并提示，不阻断交付；密钥不写入项目快照。
5. **新增闸门**：`SHOT_DURATION_MAX`（单镜超 12 秒，阻断）、`TRANSITION_FORBIDDEN`（⑭ 命中转场禁词，阻断）、`AUTO_MATCH_LOW_CONFIDENCE`（建议复核）、`EPISODE_SPLIT_UNVERIFIED`（建议复核）。14 个正文条目的定义、顺序、标签一个不改。
6. **存储**：持久化由 `localStorage` 迁移至 `IndexedDB`，工作台只挂当前集的段与镜；v1.0 浏览器草稿在首次启动时自动迁移读取。

**14 条骨架不变**：v1.1 只增加填充通道与校验，不新增、不删除、不调序、不改标签；原台词、说话人与顺序的逐字保真仍由机器校验兜底。

## 12. 交付闸门与生成范围增量（2026-09-30 二次裁定）

本节登记 v1.1 之后的第二轮裁定：**不放松真正的内容安全与台词完整性阻断，也不让导出按钮因某一条问题永久灰掉**。

1. **阻断口径收敛为事实类 + 内容安全**：继续阻断的只有输入不完整、原图描述未确认、剧本结构或台词不一致，以及转场禁词、图号占位等内容安全项。人工确认类（`DIRECTOR_UNCONFIRMED`）降为建议复核，不再是阻断项。分级由单源闸门表 `issuePolicy` 唯一决定（见第 8 节）。
2. **导出按集判定、按钮不置灰**：`导出 TXT` / `导出 Word` 仅在未载入项目或生成进行中时不可用。点击后——当前集无阻断即导出该集；当前集有阻断则打开「全书阻断清单」。
3. **全书阻断清单**：按集分组列出每个阻断项的**分类**（输入不完整 / 原图描述未确认 / 剧本结构、台词不一致 / 内容安全）、段号、镜号与原文提示，逐条可「跳转」到对应集、段、镜定位处理；同时列出**可导出集**清单并支持直接从清单按集导出，单集导出不改变当前选中的集。
4. **全部分集生成**：生成侧新增整本范围动作，逐集执行图像分析 → 参考图匹配 → 规则导演回填，单集失败隔离；整本**一次写入**并一次落盘，避免整本逐集逐段写穿存档。
5. **导演决策已生成标记**：`Segment.directorGenerated` 记录该段是否已由生成通道产出导演决策，与人工 `confirmed` 分离——前者是内容状态（段与导演板均显示「已生成」与 `已生成 X/Y 段`），后者是复核标记。生成改动过的段落 `confirmed` 回到未确认；重复执行同一批生成不改动快照（幂等）。

## 13. 资产库全局化增量（2026-10-05）

1. **资产项目级**：参考图由「归属于集」改为「归属于项目」——`project.assets` 是唯一来源，导入一次、全本共用；第 1 条已列的「导入即入全本资产库」由此实现。资产不重复存储，也不因切换分集而消失。
2. **逐集裁决**：匹配结论（置信度 / 依据）是「集 × 资产」的关系，记在 `episode.imageMatches`；资产本体上不再有置信度字段。同一张图在不同集可有不同判定，且**互不覆盖**。
3. **旧存档搬迁**：已存存档里按集存放的参考图，在**读取时自动搬进资产库**，逐图置信度转为本集匹配记账；资产本体、描述、确认状态、内置分析与段绑定一个不丢。搬迁发生在 schema 解析之前（否则未知键被剥离 → 读入即丢）。
4. **重建解耦**：重建分集（`重新规划` / 口径升级自动对账）不再需要搬运资产——资产在项目级随项目保留；`hasUserContent` 把「资产库非空」计为用户内容，导入过资产的存档不会被自动重建误伤。
5. **性能**：资产库为全局后，一次选集生成为每集各判一次主体；像素统计（主色 / 亮度 / 色温 / 光位）与集无关，按图缓存跨集复用，逐集只重算「主体 × 名册」一半。

## 14. 资产面板交互增量（2026-10-05）

1. **单入口 + 分类小框**（2026-10-05 定稿）：面板顶部是一个可点击的分类框（显示当前类别、张数、已写描述数），点击弹出**「道具 / 人物 / 场景」三个选项**的小框，选中哪一类就只渲染哪一类。类别顺序与名称单一来源（`assetKinds`），同时供小框选项与导入目标使用。**形态追加（2026-10-05 同日）**：该控件由「无边框标题 + 折叠箭头」改为**白底带边框的方框**，与面板内其余按键（导入 / 补齐描述）同款，容器不再自带底色边框（否则框套框）；箭头贴右，选项文字与张数保持左对齐。
2. **三类图片互不干扰**：切分类只换视图、不触碰数据 —— 每张图的绑定 / 描述 / 确认状态都挂在图片自己身上，切到空分类再切回来不会改动任何一类的内容。导入目标跟随当前分类：面板只有一个「导入」按钮，导到当前查看的那一类；底层仍只有一个文件选择器与一条导入代码路径。
3. **导入只入库**（裁定：「图片扔进去后是人工点击按键补齐描述，不是自动」）：导入阶段**不做图像分析、不写描述**。导入后的资产描述为空、无色卡；描述由人工点击触发。
4. **补齐双通道**：面板顶部「补齐本地描述」（文件名 + 主色卡，零 API）与新增「补齐 AI 描述」（逐张调用已配置的视觉模型）。两者都**只补空描述**、不覆盖已生成内容；AI 通道单张失败不中断整批，末尾汇报成功数，可再点一次重试。补齐本地描述时会把图像分析（色卡 / 图类理由）随描述一并入库，故色卡与图类理由在补齐后出现并持久保留。
5. **单张删除**：每张资产卡片右上角有叉号可单独删除。资产是项目级单源，删除会**解除它在所有集、所有段上的绑定**并清掉匹配记账；若该图已被集绑定、或已有描述，删除前先弹确认框并说明它被哪几集用到。删除不可撤销（重新导入同一张图即可恢复）。

## 15. 参考图图类裁决增量（2026-10-05）

1. **裁决来源改为用户所选分类**：自动匹配的图类（人物 / 场景 / 道具）**以导入时选择的分类为准**（`ReferenceImage.kind`）；本地分析按文件名猜出的 `kindGuess` 降为**界面提示**，不参与裁决。理由：用户把图放进哪一类是有意为之，是比文件名更强的证据。
2. **修复前的缺陷**：`classifyKind` 实际只能看文件名（`analyzeWithStats` 不传宽高，画幅兜底分支不可达）→ 文件名不含图类关键词时一律判 `prop` → 撞上「道具图不自动匹配段落」→ 人物图**永不绑定** → 整集 ① 人物参考图的描述为空，导出 Word 里没有任何人物描述。实测复现：`林夏.png` 落入此坑，仅改名 `林夏_人物.png` 即恢复绑定。
3. **不改匹配宽严**：用户明确归到「道具」的图仍不自动匹配；三级置信度、每段 6 张上限、未分配区口径一律不变。改的是**裁决来源**，不是放宽或收紧。
4. **提示语义对齐**：资产卡片副标题在「文件名猜测与所选分类不一致」时显示「文件名疑似 X · 仅提示，匹配按所选分类」，不再出现图摆在人物区、副标题却写「判为道具」的自相矛盾。

> 本增量只解决「人物图进不了 ①」的**第一层**（图根本没被绑定）。**第二层**仍未处理并已登记：① 的注入粒度是**段**、判据是「本段有没有台词」，不是「本镜是否入画」——无人说话的段落里人物照常入画却拿不到描述，一人镜还会写出同段其他人的描述。

## 16. 描述即生效增量（2026-10-05）

1. **取消人工「确认描述」**：三类资产（人物 / 场景 / 道具）一律**填了描述即生效** —— ① 人物参考图的描述、② 场景参考图的描述、④ 构图（道具描述随附）与校验都按 `description` 非空取值，中间不再有第二个确认动作。
2. **模型侧退役 `ReferenceImage.confirmed`**：字段已从 `imageSchema` 移除；旧存档里残留的该键在读取时由 zod 剥离（不报错、不牵动其他字段），**无需迁移脚本**。资产可用性判据从此只剩一条：**描述非空**。
3. **闸门更名**：`IMAGE_UNCONFIRMED` → **`IMAGE_UNDESCRIBED`**，判据由「描述未确认」变为「描述为空」，分类名同步为「**原图描述缺失**」；级别仍是 warning，不阻断导出。
4. **界面**：卡片不再有「确认描述」按钮，空描述改为一行状态提示「未写描述：这张图不会进入 ①②④」；分类标题的「已确认 N」改为「有描述 N」；导演板 ①②⑫ 的空值占位由「等待确认」改为「未提供（填了描述即自动写入）」。
5. **保留的确认**：`project.visual`（人物 / 场景**文字**固定锚点）的「确认设定」不受影响 —— 它确认的是人工撰写的文字设定本身，与资产描述是两回事（若也要一并取消，属另一轮裁定）。
