## 3. 关键口径

1. **只换 `label`，不动 `role`**：所有菜单项沿用 Electron 内置角色（`quit` / `undo` / `reload` / `togglefullscreen` 等），加速键与行为与默认菜单完全一致，功能零改动。
2. **叶子项一律绑定 role**：不新增无行为的死菜单。因此「文件」菜单保持与默认一致（Windows/Linux 下仅「退出」），未擅自把打开/保存/导出动作塞进菜单——那属于功能扩展，超出本次范围。
3. **正本独立成模块**：`electron/menu.ts` 不引用 `electron` 运行时，可被 Vitest 直接导入校验，避免把菜单文案埋在 `main.ts` 里而无法测试。
4. **平台分支**：`isMac` 仅决定 macOS 专属应用菜单与「文件」条目；Windows/Linux 条目结构与默认菜单一一对应。
5. **未改应用名与用户数据路径**：macOS 应用菜单文案用字面量 `剧本拆分工作台`，不改 `app.name`，避免影响 `userData` 目录。

## 5. 剩余边界

1. **系统级对话框不受控**：原生文件打开/保存对话框的按钮文案（「打开」「取消」等）由操作系统语言决定，应用侧不可改；筛选项名称已是中文。
2. **品牌与技术标识保留原文**：界面中的 `MINIMAX H3`、`SHA-256`、`AI`、镜头编号 `SC01`、时长单位 `s` 属产品名与技术标识，非界面语言，未作替换。若要求连品牌名一并中文化，需另行裁定。
3. **菜单未承载文件动作**：如希望「文件」菜单提供打开剧本 / 保存项目 / 导出 TXT / 导出 Word，需要新增 `webContents` 通道并在渲染层接线，属功能扩展，待明确后再做。
4. **沙箱护栏与代码无关**：本环境下 `npm run verify` 单条命令会在构建工具清理产物目录时触发宿主「单轮累计删除 > 50 项」护栏而中断；已按四段顺序分别独立跑通（文档契约 / Vitest / 构建 / Playwright），四条全绿。该护栏为宿主工具环境的保护机制，正常终端执行 `npm run verify` 不受影响。
