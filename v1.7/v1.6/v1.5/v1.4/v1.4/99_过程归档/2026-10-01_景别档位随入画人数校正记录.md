# ③ 景别档位随入画人数校正记录

## 老大反馈（2026-10-01 · 八次）

> 「按你的来」

上一轮登记在案、待裁定的 **E10：③ 景别「面部特写」却入画 ≥2 人**（真稿 3 例）。
老大授权按判断处理，于是没有再写一次性补丁，而是顺着这条线把**同一类缺陷**一次收干净。

## 只读核验先行：先量，不先改

真稿（倒查三代 60 集 / 4512 镜）档位 × 入画人数交叉表：

| ③ 景别 | 0 人 | 1 人 | 2 人 | 3 人 | 4 人 | 合计 |
| --- | --- | --- | --- | --- | --- | --- |
| 大全景 | 890 | 558 | 53 | 5 | 1 | 1507 |
| 过肩中景 | **138** | 2080 | 100 | 15 | — | 2333 |
| 中近景 | **171** | 388 | 94 | 5 | — | 658 |
| 面部特写 | — | 11 | **3** | — | — | 14 |

**E10 只是冰山一角。** 真正的缺陷类是「③ 景别与入画人数不相容」，两个方向都中：

1. **人物档景别套不住空镜**：138 镜「过肩中景」＋ 171 镜「中近景」落在 **0 人入画**的镜头上；
   镜里没有肩背、没有面部，写「过肩中景」就是张冠李戴。
2. **人脸特写收不下两个主体**：14 镜「面部特写」里 3 镜是两人同框。

深查 309 镜「0 人 + 人物档」的成因，**排除了「主体检测漏人」**，确认是**生成端选错档**：

| 样本 | 成因 |
| --- | --- |
| `ep-01 SC23` / `SC32` | 节拍是 `kind: 'inner'`（内心OS）→ 按设计不计入说话人 → 0 主体，但档位仍按「对话」给了「过肩中景」 |
| `ep-01 SC13` | 真·空镜（「棚子外是横店的太阳。几十个大学生群演蹲在阴凉处啃盒饭。」）→ 命中动作词「蹲」被归为 action → 给「中近景」 |
| `ep-01 SC25` | 无节拍的补位镜 → 继承上镜主体，上镜是 0 人 → 仍为 0 |

顺带挖出**第三个真 root cause**：`ep-01 SC24`「【接·视线】他抬头，看向棚外……」
以 `【` 开头，`subjectsOf` 的代词判据 `/^(?:他|她|两人…)/` 锚在**行首**，
被镜头标记挡住即失配 —— 明写「他」的镜头被判成「无人物入画」。**真稿命中 7 镜。**

## 实施（`src/platforms/minimax-h3/director.ts`）

### 1. 档位单元 `ShotGrade` + 人数校正 `gradeForShot`

把「③ 景别 / ⑤ 焦距 / ⑥ 运镜」绑成一个**升降一体的档位单元**（此前三者在同一模板对象里但无升降规则）：

```
gradeForShot(category, subjectCount)
  ├─ subjectCount ≥ 2 → pairGrades   单人档 → 双人档
  ├─ subjectCount = 0 → emptyGrades  人物档 → 空间档
  └─ 其余             → shotTemplates 基准档
```

- `pairGrades`：`面部特写` / `中近景` → **`双人中近景`（50mm）**。
- `emptyGrades`：`面部特写` / `过肩中景` → `大全景`（24mm）；`中近景` → **`全景`（35mm）**。
- 新增景深档位：`depthByScale['双人中近景' | '全景']`、`spaceDepthByScale['全景']`。

**为什么这是「同源」而不是新规则**：④ 构图的 `compositionFor` 早已有 `pair = subjects.length >= 2` 分支，
按「视线焦点落在两人视线相接的画面中部；两人之间保留视线空间，两侧各留移动余量」写 ——
也就是说 ④ 早就认定 ≥2 人是双人镜，只有 ③ 还在写「面部特写」，**③ 与 ④ 本来就自相矛盾**。
现在 ③ 与 ④ 取**同一个 `ShotGrade`**（`sourceFieldsForShot` 与 `generateEpisodeDrafts` 两处），结构上不可能再打架。

### 2. 代词判据剥离行首镜头标记

```ts
const leadingShotMarker = /^[【〔［][^】〕］]{0,12}[】〕］]\s*/u;
... pronounLed.test(joined.trim().replace(leadingShotMarker, '').trim())
```

标记集限定 `【】〔〕［］`（不使用圆括号，避免误剥正文括注）。
修后真稿命中 **7 → 4** 镜恢复继承主体；余下 3 镜上镜本身即空镜，继承结果仍为 0（语义正确）。

### 3. 审计判据升级为同源调用

`audit.ts` 不再自己写 `/特写/u`，改调 `director.scaleSubjectConflict(scale, subjectCount)` ——
生成与审计共用同一张判据表，新增/人工改写也拦得住：

```ts
export function scaleSubjectConflict(scale: string, subjectCount: number): string | null {
  if (subjectScales.has(trimmed) && subjectCount === 0) return `「${trimmed}」是人物档景别，但本镜无人物入画`;
  if (faceCloseUpScales.test(trimmed) && subjectCount >= 2) return `「${trimmed}」收不下 ${subjectCount} 个主体`;
  return null;
}
```

人工自创档位（如「中景」）不在表内 → 一律放行，仍然**宁可漏报不误报**。
`SCALE_SUBJECT_CONFLICT` 由「只查特写 × ≥2 人」扩为「**两个方向都查**」。

## 口径记录（后续不得回退）

- **③ 景别的唯一来源 = `gradeForShot(category, subjectCount)`**。
  不得再直接从 `shotTemplates[category].scale` 取档位写镜头。
- **③⑤⑥ 是一个档位单元**，升降必须整体进行，不得只改其中一项。
- **③ 与 ④ 共用同一个 grade**，`compositionFor` 的 `scale` 参数必须传校正后的档位。
- **空镜档位 = 空间档**（`大全景` / `全景`），`双人中近景` 不得出现在 0 人镜头上。
- **新增档位必须同时补 `depthByScale`**（有人）与必要的 `spaceDepthByScale`（空镜），否则构图景深会掉默认值。
- 本轮**未动** `shotTemplates` 的四条基准档与既有 `pairGrades` 之外的任何模板文案，人工既有写法不受影响。
