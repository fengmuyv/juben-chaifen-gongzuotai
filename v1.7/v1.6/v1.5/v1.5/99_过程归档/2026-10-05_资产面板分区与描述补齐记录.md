## 二、第 2 条 · 三类分区

**问题**：面板里已有「图片类型」下拉，但列表是**一锅平铺** —— 分类只体现在每张卡的小字上，人眼无法按类扫。

**改法**：

1. 列表拆成三个分区，`assetKinds`（`character / scene / prop`）为**顺序与名称的单一来源**，同时供分区列表与导入目标使用；两处各写一套的话，将来加一类资产必有一处漏改。
   - 组头 = 类别名 + 该组张数 + 已确认数；
   - 空组保留占位（「暂无场景资产」），三组常在，避免布局随数据跳动。**（同日改版为「单入口 + 分类小框」，见 §七 —— 本节描述的三组平铺已不再生效）**
2. **导入入口随分组**：每组一个「导入」按钮，`aria-label=导入人物 / 导入场景 / 导入道具`。
   - **删掉全局「图片类型」下拉** —— 它的唯一作用就是「这次导入算哪一类」，分组之后由「你在哪一组点的导入」直接表达，留着反而是两个真值来源；
   - 仍然只有**一个**隐藏 file input 与**一条**导入代码路径：`openImagePicker(kind)` 先把目标类记进 `pendingKind`，再触发同一个 input。
3. 资产卡片抽成 `renderAsset(image)`（三组共用同一张卡）—— 第 4 条的叉号因此只需加一处。

## 三、第 3 条 · 描述补齐改人工触发 + 新增「补齐 AI 描述」

**问题**：导入即自动跑图像分析并写描述，人看到的是「已经填好了」的样子，但那是机器给的占位描述；同时逐张解码采样是导入阶段的主要耗时。

**改法（导入只入库）**：

```ts
// src/App.tsx · pickImages
for (const file of list) {
  try { prepared.push(await prepareImage(file, kind)); } catch { failed += 1; }
}
```

导入路径**不再**调用 `analyzeImage` / `buildLocalDescription`（契约脚本已加防回流断言）。结果：

| 时机 | 导入后 | 点「补齐本地描述」后 |
|---|---|---|
| 描述 | 空 | `文件名；主色：#…、#…` |
| 图像分析（色卡 / 图类理由） | 无 | 随描述一并落库 |

**新增「补齐 AI 描述」**（老大点名的可选项）：

- 只处理**描述为空**的资产（已生成的不覆盖，重做请先「清空描述」）；
- 未配置接口地址 / 模型时给明确提示，不静默失败；
- 逐张调用视觉模型，**单张失败不中断整批**（网络分批失败是常态），末尾统一汇报 `完成 n/N`，未成功的仍是空描述、可再点一次重试；
- 走面板顶部进度条（`setProgress`），几十张时可见进度。

**一处连带设计**：`store.updateImage(id, description, analysis?)` 增加可选第三参。补齐本地描述时把 `analysis` 一并落库 —— 否则「导入零计算」会让色卡与图类理由**永远不出现**（`describeLocalOne` 原本只在内存里算、不存）。现在语义是「补齐时才计算，且算完就存」。

卡片文案同步改：占位由「导入后会自动生成本地描述」改为「描述待补齐：点『本地生成描述』或『AI 生成描述』，也可直接人工填写（导入不会自动生成）」。

## 四、第 4 条 · 单张删除

**改法**：

- `store.removeImage(id)`（第 1 条已落地）：资产库出清 + **所有集、所有段**解除绑定 + 清掉 `imageMatches[id]`；未命中即返回原对象（幂等）。
- 界面：卡片右上角叉号 `.image-remove`（`aria-label=删除<文件名>`，`position: absolute`）；点击走 App 内的 `removeAsset(image)` —— **影响范围判定集中在这一个函数里**，卡片只负责触发。
- **影响范围确认**：资产是项目级单源，删一张即全本失效，所以
  - 被任何集绑定 / 已有描述 / 已确认 → `window.confirm` 并**说清它被哪几集用到**（「已被 1 集绑定：第01集；删除后这些段的绑定一并解除」）；
  - 纯空白、无人引用的图直接删（不值得为一次误点弹窗）。
- 删除后 toast 提示「已删除资产『×』，全本绑定一并解除」。

## 六、剩余边界

- 删除**不做撤销**（叉号前有影响范围确认）；要找回需重新导入同一张图。
- 未做「该资产被哪些集引用」的常驻计数（只在删除确认框里列出集名）。
- 「补齐 AI 描述」逐张串行调用，未做并发与限流（串行是为了让失败面最小、进度可信）。

## 七、改版：三类分区 → 单入口 + 分类小框（同日追加）

**老大原话**：

> 「现在的有那个味道了，但是还不是我的要求，把图片中人物那个位置做一个点击后出现道具，人物，场景三个选项的小框，三个选项中的图片互不干扰」

**问题**：三组上下平铺占满面板 —— 某一类张数多时（如人物 47 张），其余两类被挤到很下面；且三类同时铺出来，视线无法聚焦到当前要处理的那一类。

**改法**：

1. **单入口**：撤掉三组各自的分组头，换成一个可点击的分类标题 —— 显示「当前类别 · 张数 · 已确认数」+ 折叠箭头（`ChevronDown`，展开时旋转 180°）。
2. **分类小框**：点标题弹出 `.asset-kind-menu`（`role="menu"`），三个选项 `role="menuitemradio"` 各带自己的张数，当前项高亮；选中即切换并关闭小框。
   - 关闭时机：`pointerdown` 捕获「点小框外任意处」+ `Esc` 键（`useEffect` 内挂 `document` 监听，开才挂、关即卸）。
3. **互不干扰的实现**：`activeAssetKind` **只决定渲染哪一类**，不参与任何数据写入 ——

   ```tsx
   const items = assets.filter((image) => image.kind === activeAssetKind);
   ```

   绑定（`segment.imageIds`）/ 描述 / 确认状态都挂在**图片自己**身上，所以切分类只是换视图：切到空的「场景」再切回「人物」，那两张原样还在。
4. **导入目标跟随当前分类**：面板只剩一个「导入」按钮（`aria-label=导入<当前类>`），替代原先三组各一个的按钮；`pendingKind` 由 `activeAssetKind` 决定。
5. **默认分类 = 人物**（`character`），与 `assetKinds` 顺序首位一致。

**验证（本次）**：

- `npx tsc --noEmit` 通过；
- e2e（批量导入用例）改写为：默认单面板 → 人物 2 张 → 点标题弹小框 → 切「场景」得 0 张 → 切回「人物」仍是 2 张（**互不干扰的正向证据**）；
- 文档契约新增 2 条防回流断言：`asset-kind-menu` 必须在（否则视为回退到三组平铺）、`activeAssetKind` 必须在（否则三类会互相干扰）。
