# 通用 AI 接入层实施记录

## 目标

把「接口设置」做成一个通用接入层，并把配置负担降到最低：

1. 一个密钥可接市面上所有通用语言大模型；
2. **界面不出现厂商选择** —— 由接口地址自动识别厂商与协议；
3. **界面不出现密钥输入框** —— 密钥由主进程从本机私有配置读取，全程不经过渲染层；
4. 接入后可列出该密钥可见的模型并选择思考强度。

## 技术路线裁定

先试用第三方 SDK（`openai` 官方 SDK / Vercel AI SDK `generateObject`），**实测不可行**：本机 `npm install` 反复挂死（并发两个后台安装互相锁死，单次安装亦长时间无输出；`--cache=E:/wb_temp/npm-cache` 后仍无法在合理时间内完成），而 `npm view ai version` 秒回，说明是安装环节受限而非网络问题。

据此定为**零依赖自研**，依据是：除 Anthropic 使用 Messages 协议外，**市面上其余厂商（含全部国产）都提供 OpenAI 兼容端点**，因此两张协议实现即可覆盖全集；引入 AI SDK 反而需要为每家单独安装 provider 包。结论：**留通用自研模块，不引入 `openai` / `@ai-sdk`**（`package.json` 依赖中无任何 AI SDK）。

## 实测证据（2026-10-04，对第三方中转，域名已隐去）

| 调用 | 结果 |
| --- | --- |
| `GET /v1/models` 带密钥 | 200，返回 1 个模型 |
| `GET /v1/models` 不带密钥 | **401** `Invalid token` |
| `POST /v1/chat/completions` 带密钥 | 200，正常出字 |
| `POST /v1/chat/completions` 不带密钥 | **401** `Invalid token` |
| 带 `reasoning_effort: high` | 200（该中转接受推理强度参数） |
| 带 `temperature: 0` | 200 |
| 地址只写到 `/v1` | 200（路径由程序拼接） |

结论：密钥**不能省**（匿名调用一律 401），但可以做到「用户不必手填、界面不显示」。

## 实施

### 单源模块

- `electron/ai-providers.ts`（厂商注册表，唯一来源）：24 家预设 = 国际 6 ＋ 国产 13 ＋ 聚合与本地 5。新增 `providerFromURL(baseURL)` —— **按 host 自动认领预设**，命中注册表就用该预设（如 `api.anthropic.com` → Messages 协议），认不出的地址（第三方中转、自建网关）回落 `custom` 按 OpenAI 兼容处理。新增厂商仍然只是加一行。
- `electron/ai-client.ts`（唯一请求出口）：`generate` / `listModels` 的入参由「厂商 + 地址」简化为 **只有地址**，协议在内部由地址识别。Anthropic 走 `/messages`（`x-api-key`、顶层 `system`、必带 `max_tokens`、图片 base64 数组）；其余走 OpenAI 兼容 `/chat/completions`。思考强度统一四档，映射为 `thinking.budget_tokens` 或 `reasoning_effort`；`off` 时一律不下发推理参数，避免不被识别而 400。端点守卫仅放行 HTTPS 与本机回环；一切对外错误文案先经 `redact()` 脱敏，绝不回显密钥或请求头。

### 密钥通路（界面不可见）

- 新增 `electron/credentials.ts`：解析本机 `.env.local`，取 `WORKBENCH_API_KEY`。
  - **关键点**：Vite 只把 `VITE_` 前缀的变量注入浏览器构建产物，本模块读取的是**无前缀**键名，且读取发生在主进程，故密钥既不进 `dist/`，也不经 IPC 回流到界面。
  - 对外只有两个口：`credentialsStatus()` 返回 `{ configured, endpoint, model }`（**密钥退化为布尔量**），以及供调用方补齐请求头的 `requireLocalApiKey()`。
  - 纯函数 `parseEnvFile` / `credentialsFromText` / `statusFrom` 与文件读取分离，便于无副作用测试。
- `electron/main.ts` 新增 `credentials:status` IPC；`electron/preload.cts` 暴露 `workbench.credentials()`。
- `electron/vision.ts` / `script.ts`：`apiKey` 与 `endpoint` 改为可选，留空时由主进程用本机配置补齐；`provider` 字段整体移除。
- `.env.local`：地址改为只到 `/v1`，新增 `WORKBENCH_API_KEY`（该文件已被 `.gitignore` 的 `.env*` 排除，`git check-ignore` 实测确认）。

### 界面

- `src/App.tsx` 接口面板：**删除厂商下拉、删除密钥输入框**，保留「接口地址（只到 /v1）→ 模型 → 思考强度 → 接入并拉取模型」，并新增一行状态文案说明本机密钥是否已配置。
- `src/core/vision.ts`：`AiTarget` 只留 `endpoint` / `effort`；新增 `requestCredentialsStatus()`；请求类型不再带 `apiKey`。

## 验证

- `npx tsc --noEmit` 与 `tsc -p tsconfig.electron.json --noEmit`：均 0 错。
- `npm test`：6 个测试文件、**142 项**通过。新增覆盖：按地址识别厂商（含未知中转回落）、不指名言厂商也能走对端点与协议、未识别中转默认不下发推理参数、`#` 不被当作注释、**状态对象序列化后不含密钥明文**、缺失配置目录不抛错。
- `npm run build`：TypeScript、Vite 与 Electron 构建通过。
- `npm run test:docs`：PASS。
- Playwright 全量 **17/17** 通过（含桌面端）。断言改为「界面既无厂商下拉、也无任何 password 输入框」，桌面端另加断言 `workbench.credentials` 为函数且面板无密钥框。

## 遗留

- 小米 MiMo 端点待官方公布后补 `baseURL`（现按自填端点处理）。
- 密钥以明文存于本机 `.env.local`（被版本库忽略）；若要连本机明文都不留，可后续改接系统凭据管理器。
- 第三方 SDK 路线在本机不可用（安装环节受限），如环境恢复可再评估；当前零依赖方案已覆盖全部目标厂商。

## 后续细化（同日 · 复审后收敛）

1. **去厂商下拉** —— 改由 `providerFromURL(baseURL)` 按接口地址 host 自动认领预设，界面不再出现「厂商」；认不出的地址（第三方中转、自建网关）回落 OpenAI 兼容。
2. **去密钥输入框** —— 密钥由主进程从本机 `.env.local` 读取，界面只保留一行状态（已配置 / 未配置），不再要求手填；对外只回 `{ configured, endpoint, model }`。
3. **两项标签中英双显** —— `src/App.tsx` 接口面板标签改为 `接口地址（API URL）` 与 `密钥（API Key）`。

配套护栏：`tests/e2e/workbench.spec.ts` 断言两条中英对照标签可见，且界面既无 `厂商` 也无 `input[type="password"]`；`tests/方案文档.Tests.ps1` 新增两条断言锁定标签，防止被后续「英文残留清理」误删。该护栏与 `desktop.spec` 的「应用菜单为全中文」用例互不冲突 —— 后者只遍历**菜单项 label**，与界面标签无关。

## 再细化（同日 · 密钥改回可手填、标签英文在前）

老大看图后指出：**「密钥要显示自己填，以 key（密钥）这种形式显示，url 也是」**。据此对上一节的收敛做两项修正：

1. **恢复密钥输入框** —— `src/App.tsx` 新增 `key（密钥）` 输入框（`type="password"`、`autoComplete="off"`、初始为空、**绝不复显本机配置的密钥**）。语义 = 「填了就用填的，留空则由主进程回落本机私有配置」，本机配置的便利性保留。
   - **保密纪律不变**：手填密钥**只驻留 React state（内存）**，`saveSettings` 刻意不写 `localStorage`，刷新即清空。`AiTarget`（`src/core/vision.ts`）与主进程 `vision.ts` / `script.ts` 的 `apiKey` 均为可选透传，落点仍是 `request.apiKey?.trim() || requireLocalApiKey()`。
   - e2e 新增机器化护栏：手填 `sk-e2e-probe-not-a-real-key` 后，遍历 `localStorage` 全部值断言不含该串。
2. **标签改为英文在前** —— `接口地址（API URL）` → **`url（接口地址）`**；`密钥（API Key）` → **`key（密钥）`**。面板说明文案同步改为「密钥可直接填写，留空则使用本机私有配置中的密钥」；状态行标签改为「本机密钥」（三态文案：正在检查本机配置… / 已配置，上方留空即用它。/ 未配置，请在上方填写，或在工程目录的 .env.local 设置 WORKBENCH_API_KEY。）。

契约同步：`tests/方案文档.Tests.ps1` 的中英对照断言改为 `url（接口地址）` / `key（密钥）`，并新增「密钥框存在 + 密码类型 + 不得写入本地存储」三条护栏；`desktop.spec` 与 `workbench.spec` 原「面板无 password 框」断言反转为「有且仅有一个」。

3. **模型项延迟出现** —— 老大要求「在 url 和 key 都（填）之前不显示模型名称」。判据 = `endpoint.trim() !== '' && (apiKey.trim() !== '' || localCredentials?.configured === true)`，即**地址非空**且**（手填了密钥 或 本机已配置密钥）**；就绪后沿用本机配置的模型名。
   - 契约新增两条断言（锁定实现注释与就绪判据字面）；e2e 断言初始 `模型` 计数为 0，手填密钥后才出现且带出本机配置的模型名。
