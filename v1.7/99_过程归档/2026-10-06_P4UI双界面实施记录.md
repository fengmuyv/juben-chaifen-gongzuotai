## 3. 三条设计纪律

### 3.1 折叠即卸载，且开合状态留在编排层

段内容是 `{open && children}`（不渲染 DOM、也不做整本解析），与 `SourcePane` 既有的
「折叠态不解析整本识别结果」是同一条纪律。**开合状态必须留在编排层**：
「分集清单」的整本解析被 `useMemo` 门在 `splitOpen` 上（`splitEpisodes` 大剧本一次数百毫秒），
开关若下沉进 `Section`，那个 memo 就失了依据，整本解析会重新回到启动路径上。

代价是折叠时内容组件的局部状态会重置 —— 所以 `SourcePane` 的「已改未存」必须
`onDirtyChange` 上抛给摘要行（`剧本原稿 · 1.2 万字 · 未保存`），否则折叠一次就把没保存的编辑静默丢掉。

### 3.2 `data-section` 是 e2e 的定位锚，不是装饰

左栏里含「资产」二字的按钮不止一个（三框各有「清空本类全部资产」），按无障碍名取会命中多个。
`Section` 把段名写在段头按钮的 `data-section` 上，e2e 用 `.rail-section-head[data-section="…"]` 精确定位。

### 3.3 入口分侧 ≠ 数据分侧

「人物设定与弧光」**仅 AI 态渲染**，但 `project.visual` 是**数据侧两侧都在消费**的：

- `skeleton.ts` 的 `values()` 在无资产描述时把它作为 ① ② 的文字兜底（`文字设定：…`）；
- `validator.ts` 的 `VISUAL_UNCONFIRMED` 与相邻段锚点漂移比对也取它。

所以本地模式**只是不提供录入入口**，而不是「本地不消费」——已有锚点的老项目切到本地模式照常生效。
**刻意不做任何数据侧收口**：删掉 `values()` 的 `文字设定：…` 回落会让**已有存档**导出产物里的
① ② 一起变空，那是拿老数据降级换新界面。这条已写成护栏断言。

### 4.1 e2e 破面与三条改法

左栏四段**默认收起**这一点会让一票旧用例在收起态取不到元素（`原剧本编辑区`、`.image-item` 等
会稳定取到 0 个，且报错方向误导）。改法是加一个 `openSection(page, name)` 助手，
在需要处先展开；**不是**把段改成默认展开（那违背定稿）。

三类具体处置：

1. **`原剧本编辑区` / `保存原稿版本`（11 处）**：先 `openSection(page, '剧本原稿')`。
2. **`.image-item` / `导入人物` / `asset-group*`（16 处）**：先 `openSection(page, '资产')`；
   凡 `reload` 之后的用例都要**重新展开**（`openAssets` 属编排层 state，reload 即重置）。
3. **`人物固定锚点` / `场景固定锚点` / `确认设定`（3 处）**：改到 AI 态断言。
   其中「已完成的一集可直接导出」这条用例里原本有「填锚点 → 确认设定」两步，
   **自本步起已不在本地路径上**，故删除；这不影响其结论 ——
   `VISUAL_UNCONFIRMED` 与 `CHARACTER_ANCHOR` 本就都是 warning，人工确认类判据不阻断导出。
   移动端用例里对锚点的断言改为「顶栏分段控件 + 展开后的原剧本编辑区」，
   锚点可达性移交 AI 用例覆盖。

另外两条口径调整：

- **「带参考图的存档打开不卡顿」的 DOM 就绪口径**由「等 `.image-item` 计数」改为
  「等 `.segment-strip button`」。参考图现在在折叠段里，继续用旧口径会把
  「reload + 手动展开段」的耗时混进启动耗时。展开后仍验「图真的解码」（先滚进视口再断言 `src`）。
- **`getByText('原剧本')`** 之类的断言在展开后依然成立（`h2` 只在段内）。

### 4.2 一次超时失败与对照实测（不猜）

整轮首次跑出现 1 条失败：`生成作业可暂停、可继续、可终止…` 撞 30s test timeout。
trace 取证把 **27s 精确归属到 `fill()` 这一个动作**（往 `<textarea>` 灌 52×4×16 的密集稿）。

为区分「性能回归」与「用例余量不足」，做了一次**同条件单跑对照**：

| 版本 | 单跑耗时 | 结果 |
|---|---|---|
| P4 第二小步之前（`e11edda`） | **24.6s** | 通过 |
| P4 第二小步（本次） | **25.4s** | 通过 |

**差 0.8s，属正常波动 → 无性能回归**。真因是 Playwright 默认 30s 的 test timeout
与这批判据的规模不自洽：余量仅约 5s，两个 worker 并行时即越线。

并在 spec 里写明依据与实测数据。**这不是放宽验收** —— 断言一条未减，
只是不再让默认 timeout 切断长流程（它们内部本就写着 `timeout: 30000` 的 step 等待）。

### 6.2 一处方案内部矛盾的解读（已按此落地，留痕待复核）

方案 §5.1 的差异表把「右栏末项」写成「AI 版**无** / 本地版**本集校验**卡」，
而批 2 裁定「**合并 + 保留预览页签**」。两者并读会得出「AI 态连成品预览也没有了」——
那会让 AI 态**看不到自己刚生成的东西**，与「审阅」二字相悖。

本步按**可同时满足两条约束**的读法落地：

| 引擎态 | 右栏末项 |
|---|---|
| 本地 | 页签一 **本集校验**（逐 P 对账行 + 问题清单）· 页签二 **分镜预览** |
| AI | **只有成品预览**（页签条整体不渲染 —— 单页签的条是噪音） |

`preview` 的判据同步补 `aiReady` —— 否则切成 AI 态那一刻预览为空，右栏末项闪一帧白屏。

### 6.4 四条设计纪律

1. **整 P 铺开的直接后果：同名输入框变多。** 每镜一套 14 格 ⇒ `getByLabel('衔接')`、
   `getByLabel('构图')` 这类断言会命中多个（Playwright strict mode 直接报错）。
   处置是**一律 scoped 到 `.shot-card`**，而非给 `aria-label` 拼镜号 ——
   后者会让 label 与 `skeleton` 正本不再逐字一致，取值口就多了一份隐含约定。
2. **卡片头承担只读派生位。** 导演意图（`purpose`）不再有独立输入框：它是只读派生位，
   且与标题行同源。把「有值且 readonly」的结构性断言换成「卡头含该文案 + 全局不存在
   `导演意图` 输入框」，语义更准。
3. **三个只读位与 `protectedKeys` 一一对应**（`character` / `scene` / `dialogue`）：
   ①② 标「资产」、⑫ 标「原稿」。把来源写在格子上，用户才不会以为「这格我填不了是坏了」。
4. **单 P 重生的上下文取「上一段的板上结果」**（`draftsOnBoard`），不是空上下文 ——
   与整集路径「回退段也算上段结果」同一条纪律：下一段要接的是**板上状态**，不是理想状态，
   否则这一段会「跳」出整集的影调与轴线。覆盖语义沿用顶栏「覆盖已有内容」开关，
   未勾选时只补空白，**人工改写过的字段不会被冲掉**。

### 7.3 一处实测缺陷与修复（凭截图起疑 → 用探针定性）

首轮取证截图里 **P 索引条与卡头都不见了**。截图只能说明「看起来不对」，
故加探针读 DOM 定性（**不靠看图下结论**）：

| 探针项 | 修复前 | 修复后 |
|---|---|---|
| `.director-pane` 的 `scrollTop` | **281** | **0** |
| P 索引条 `boundingBox.y` | **-35.7**（已在视口上方） | 245.3 |
| 首卡 `boundingBox` | y=190 · 高 **1104.75** | y=471 · 高 1104.75 |
| 可视区 `clientHeight` | **585**（`scrollHeight` 5861） | 585 |

**根因**：卡片远高于可视区（1104 vs 585），而初版 `useEffect` 无条件 `scrollIntoView`；
更要命的是「切段」必然伴随 `selectedShot` 被改写成该段首镜（`store.selectSegment`），
**无法靠「镜是否变」区分用户意图** —— 于是初始加载与换段都被当成「跳转到某镜」而滚动。

**修法**（`DirectorPane` 改为按**段是否变**优先）：

1. 段变 → `scrollTo({ top: 0 })`（停在段头：用户看到 P 索引条 + 段头）；
2. 同段内镜变（「全书清单」跳转）→ 才把那一卡滚入视口；
3. 首次挂载两者都未变 → 什么都不做（页面天然停在段头）。

另加 `.shot-card { scroll-margin-top: 62px }`，跳转时卡头不被 sticky 的 `.pane-title`（55px）遮住。

**已固化为断言**：`expect(await page.locator('.director-pane').evaluate((node) => node.scrollTop)).toBe(0)` ——
这条不写下来，下次加个 `scrollIntoView` 就会静默复发（且只在截图里看得出来）。

**已知取舍**：「全书清单」的**跨段**跳转会落到该段**段头**而非那一卡（段变优先于镜变）。
清单每条本就写了 `segmentId · shotId`，且目标卡带 `.selected` 高亮，向下滚即可见；
若日后要「跨段精确落到卡」，需由编排层显式传入滚动意图，而不是靠猜。

### 7.2 第二次实测：e2e 进程退出与否是**偶发**，不是必然

本步第一轮 e2e 跑满 **10m40s** 仍未退出（无 `.last-run.json`，与 a 阶段那次同形），被主动收掉；
改用 `--reporter=list` 重定向到日志后再跑，**1.6m 正常退出、`EXIT=0`、25 条全绿**。

两次同代码、同命令，差异只在输出通道 —— 故「teardown 挂死」应记为**偶发**（成因未定），
排查时以「`ok` 计数 == spec 内 `test(` 计数」或 `.last-run.json` 为判据，**不要**把「进程没退出」当成失败。
