## 3. 边界怎么划的

1. **state 归属看「谁的生命期与谁一致」**。项目级 state 一律留在 `App.tsx`；只有「只在单个面板内使用、且面板卸载后本就不该存在」的才下沉 —— 本轮只下沉了 `imageInput` / `pendingKind` 两个 ref。
2. **`activeAssetKind` / `kindMenuOpen` / `kindMenuRef` 刻意留在编排层**：面板在「清空工作台 → 重新导入」这条路径上会整体卸载重挂，这两个状态若放进面板，会被重置成默认分类、菜单态丢失 —— 那就是行为变化。同理 `ignoredGateIssues` 留在编排层：关闭清单只卸载视图，重开时忽略记录必须还在。
3. `Thumb`（视口门控缩略图）、`assetKinds` 单源、`renderAsset` / `removeAsset` / `pickImages` 等只服务资产面板的逻辑随面板一起下沉；`aiSegmentDrafts` / `contextAfter` / `checkpoint` / `oneClick` / `generateEpisodes` / `exportTarget` 等编排逻辑留在 `App.tsx`。

## 4. 「零变化」怎么证的（不是口头保证）

**① DOM 结构逐项对账**（`git show HEAD:src/App.tsx` 对照拆后 8 个文件合并文本）：

- **19 项标签计数逐一相同**：`className="` 109、`aria-label=` 34、`title=` 21、`<button` 51、`<input` 10、`<textarea` 5、`<select` 5、`<label` 15、`<section` 4、`<div` 76、`<p ` 10、`<span` 32、`<strong` 13、`<small` 6、`<table` 1、`<details` 1、`<h3` 5、`<h2` 3、`<pre` 1。
- **`className` 值分布零差异**、**`aria-label` 值分布零差异**（比的是类名与标签文案本身，不只是数量）。
- 由此保证 e2e 依赖的选择器（`.input-image-pane` / `.director-pane` / `.image-item` / `.progress-panel` / `getByLabel('人物资产')`）逐个不受影响。

**② 测试四件套**：`npx tsc --noEmit` 通过；`npm test` 195/195 通过；`npm run test:docs` PASS；`npm run build` 成功。e2e 结论见 §6。
