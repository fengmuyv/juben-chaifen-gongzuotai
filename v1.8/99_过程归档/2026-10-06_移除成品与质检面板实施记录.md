# 移除「H3 成品与质检」面板实施记录（2026-10-06）

> 来源：老大截图（右栏末项「H3 成品与质检」整块）＋ 原话 **「这块不要了」**；
> 追问澄清为「只删成品与质检」，即**整个面板**（页签条 + 逐 P 对账行 + 问题清单 + 整集预览 + 底部入口）一并移除。

## 一、被删的是什么

`src/panes/ResultPane.tsx`（右栏末项，P4 第二小步 b 落地）由四块组成：

| 块 | 内容 |
|---|---|
| 标题行 | `.pane-title`「H3 成品与质检」＋ 右侧 `本集可导出 / N 项阻断` 计数 |
| 页签条 | `.result-tabs`：**本集校验**（带问题数徽标） / **分镜预览**；仅本地态渲染 |
| 本集校验页 | `.review-rows` 逐 P 对账行（段号 / 模式 / 镜数 / 是否已生成 / 阻断与复核计数 / 「定位」）＋ `.issues` 问题清单 |
| 分镜预览页 | `.preview`：`compiler.previewText` 的整集分镜文本 |
| 底部 | `.result-footer`：版本说明 ＋ 「全书清单」入口 |

右栏本来是「导演板 + 成品与质检」上下堆叠（`.right-col .result-pane { flex: 0 0 42% }`），
删除后右栏**只剩导演板**，导演板独占整栏。

## 二、关键取舍（三处刻意保留，一处刻意删掉）

1. **删界面 ≠ 删校验。** `issues` / `validationState` / `errors` / `scheduleValidation(project, 180)` 一律原样保留。
   顶栏两枚导出按钮的 `title` 仍据 `errors.length` 给出「本集 N 项阻断，点击查看全书清单」——
   删掉面板只意味着**问题清单少了一个展示位**，校验本身与它的消费点一个都没少。
2. **质检入口仍可达。** 面板底部那枚「全书清单」按钮消失，但顶栏「导出 TXT / 导出 Word」本就会在阻断时打开
   `GatePanel`（全书阻断清单），入口未断；且「片段导出」的闸门同样直达该清单。
3. **闸门清单的「跳转」改落点。** `GatePanel` 的 `onTabIssues` 这个 prop 随之删除（它唯一的作用是把右栏切到
   「本集校验」页签）。跳转仍做两件事：`store.focusTarget(episodeId, segmentId, shotId)` 定位 + `onClose()` 关清单——
   落点由导演板那枚 `.shot-card.selected` 承接（e2e 已按此断言）。
4. **`GatePanel` 的计数样式不受牵连。** `.gate-summary .error-count` / `.ready-count` 是独立一组，
   随面板删掉的只有 `.pane-title .error-count` / `.ready-count`（面板标题行专用）。

## 四、测试面：为什么是「负向锁死」而不是删除断言

面板的断言不能只是删掉——**删断言 = 失去防回流**。本次一律翻成负向锁死：

| 原断言 | 改法 |
|---|---|
| `.review-row` 行数 == P 索引条按钮数 | `-not (Test-Path src/panes/ResultPane.tsx)` ＋ `-not $app.Contains('panes/ResultPane')` / `'<ResultPane'` |
| 「本集校验」按钮可见 / AI 态计数 0 | `expect(page.locator('.result-pane')).toHaveCount(0)` ＋ `.preview` 计数 0 |
| `.preview` 含 `①…` / `⑭…` | 迁到卡片：`.shot-card` 首格的 `人物参考图的描述` 与末格的 `衔接` |
| `.preview` 含 `③ 景别：过肩中景` 等生成值 | 迁到卡片：`page.locator('.shot-card textarea')` 的取值数组必须含 `过肩中景`（与预览同一份 `gradeForShot`） |
| `.preview` 含人工修订的 `生成后仍可人工修订` | 迁到卡片：该 `微表情` textarea 的 `toHaveValue` |
| 跳转后「本集校验」可见 | 改为 `.shot-card.selected` 计数 1（跳转的真实落点） |
| `.review-row {` 有样式 | `-not $stylesBody.Contains(...)` 逐条清孤儿规则 |

**锚点纪律（本轮踩过）**：负向锁定的 `$app.Contains(...)` **必须锚在「代码形状」上**——
`'panes/ResultPane'` / `'<ResultPane'` / `'previewText('` / `'setTab('` / `'onTabIssues'`，
而**不能**锚裸标识符 `'ResultPane'` / `'previewText'`。原因是代码注释与归档会**如实**写下
「已被移除的 `ResultPane`」「与 `compiler.previewText` 同源」，裸标识符断言会把这类留痕误判成回流
（`DirectorPane.tsx` 的注释里就有 `compiler.previewText`，第一版断言正是被它拦下的）。

改法是**每轮给一个全新空目录**（`pw-out-<用途>-<序号>`），而不是反复复用同一个。

## 六、边界与未做

- 「本集校验」看板（逐 P 对账行 + 问题清单）**没有替代落点**：它提供的是「本集各段是否已生成 / 各自几项阻断」
  这一眼总览，删掉后面上只剩顶栏那个 `errors.length` 总数。这是老大的明确裁定，**不做补偿性设计**。
- 段落级「已生成」的语义缺陷（`store.ts` 的 `marked = true`，见 `2026-10-06_片段导出实施记录.md` §二）
  仍未修，与本轮界面收缩无关。
