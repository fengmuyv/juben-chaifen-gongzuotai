## 三、护栏扩到文档层（本次的技术核心）

### 3.1 判据为什么必须收窄

照搬代码侧的「未登记 URL 主机」判据到文档层会**直接变成假护栏**，实测两组数据：

1. 文档层 `.md` 里带 `http://` / `https://` 前缀的 URL 现在是 **0 处** —— **本轮泄漏形态正是裸域名**
   （`host:443`），带前缀的判据**一处都抓不到**；
2. 改测「裸点分标识符」：200+ 条命中，其中**真域名只有 3 个**，其余全是代码标识符
   （`visual.cast` / `draft.source` / `JSON.stringify` / `z.array` …）与「文件:行号」引用（`planner.ts:145`）。

**结论**：任何「裸域名」通用判据都会全量假红。**只保留两条高精度判据**：

| # | 判据 | 说明 |
|---|---|---|
| ① | `协议://host` | host 走白名单（保留域 / 本机回环 / 厂商注册表 / `www.w3.org`） |
| ② | `host:端口`（host 必须含点） | host 走白名单；**host 以源文件扩展名结尾的直接跳过**（「文件:行号」引用）；**版号形态 `v1.1` / `1.8.0` / `9.30` 跳过**；**本机回环**则要求 `host:端口` **在代码侧真实出现过** |

判据 ② 的本机回环分支是堵住「把手填的本机代理端口抄进文档」的关键 —— 端口白名单**不枚举**，
从代码侧（`src/` `electron/` `tests/` + `package.json` / `playwright.config.ts` 等）**派生**。

### 3.2 两次踩坑（都已修）

1. **「末段是数字就跳过」误杀 IP** —— 首版用「host 末段是纯数字 → 视为版本号跳过」，结果
   `127.0.0.1:<port>` 的末段是数字，**被连带跳过、漏报**（真护栏验证时才发现：退回脱敏前状态，
   护栏只报了 3 个文件的域名条目，代理端口一处没报）。改为按**版号形态正则**（`^v?[0-9]+(\.[0-9]+){1,2}$`，
   段数 ≤3）精确排除 —— IP 是 4 段，不再被误杀。
2. **`git grep` 不支持非捕获组** —— POSIX ERE 里 `(?:...)` 报 `Invalid preceding regular expression`，
   实测阶段改用普通组；`.NET` 正则（PowerShell 内）支持非捕获组，故最终实现无此问题。
3. **`.ps1` 是两头都不管的盲区** —— 写护栏注释时把真实域名与端口抄了进去，复扫才发现：契约测试文件
   既不在代码侧扫描面（只含 `.ts` / `.tsx` / `.cts`）、也不在文档层（只含 `.md`）。
   修法有二：注释改中性表述，且把 `tests/**/*.ps1` **纳入代码侧扫描面**。

### 3.3 真护栏验证（不采信「跟着新代码写的」）

| 状态 | 结果 |
|---|---|
| **当前（脱敏后）** | `npm run test:docs` → **EXIT=0 PASS**（文档层零假红，代码层零假红） |
| **退回脱敏前**（`git stash push -- <三文件>`） | `npm run test:docs` → **EXIT=1 FAIL**，报出 `host`（3 文件条目）＋ **`127.0.0.1:<port>`** |

即：新判据在**旧状态**下必然失败、在**新状态**下通过 —— 不是「跟着新代码写的」摆设。

**附带一个实证**：首次跑 `test:docs` 时，新护栏报出**本文件**两处 —— 一处是写「踩坑经过」时把**真实的
本机端口**带了出来，另一处是**带协议前缀的占位符域名**被判据① 当成未登记域名；两处已改为不含真实值
的表述。**这本身就是护栏有效的最好证据** —— 它不认「这是文档在讲自己」，只认形态。

## 六、边界与遗留

- **残余盲区（如实记录，靠人工复核）**：**不带协议前缀、不带端口**的裸域名（如 `host/v1`）无法与
  代码标识符区分，本护栏**不覆盖**。本次 8 处全部落在两条判据内（已实测），故本轮风险已闭合，
  但该形态仍需上传前人工扫一眼。**扫描面边界**：文档层只覆盖 `00_索引` / `01_产品方案` /
  `02_技术方案` / `99_过程归档` 的 `.md` ＋ `agents.md`；`resources/skills/**` 的技能包正文
  （`SKILL.md` / `prompt.md`）**未纳入**（含大量外部参考链接，纳入需先建其白名单），仍靠人工复核。
- **★ 残余盲区被真实命中过一次（2026-10-06 推送后终检）**：推完 v1.6 做**整包 tarball 全树扫描**，
  仍命中 **1 处** —— **本文件自己**写了「私有域名的关键词原文」（作为「我扫的是什么」的说明）。
  它既不带协议、也不带端口，正好落在上面那条残余盲区里。**根因不止一个**：① 护栏与「裸词」形态
  都不覆盖这类写法；② 手工复扫时用了 `git grep` —— 它**默认不搜未跟踪文件**，而当时本文件还是
  untracked（`??`），于是**漏扫**。**两条教训**：**上传前扫描必须扫工作区磁盘上的文件**（护栏用
  `Get-ChildItem` 是对的，不能用 `git grep` 代替）；凡是「讲自己扫了什么」的句子，**不要写出被扫
  关键词的原文**。已按此改掉该词，并**回滚远端 main 到推送前提交后重推** v1.6。
- **P1 本机路径保留**：老大裁定 `sourcePath` 维持现状（技能包既有设计、私有库、仅暴露用户名）。
- **历史归档不追改**：本次脱敏属「历史不追改」的**敏感例外**（照 v1.5 先例），只改被点名的 8 处，
  不做全库重写。
