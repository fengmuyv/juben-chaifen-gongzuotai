# 「已生成」标记语义修正实施记录（2026-10-06）

> 来源：老大截图（P 索引条 P01–P14 全带「已生成」）+ 原话
> **「哎依次推理是 1p1p 的推理，不是一键同步推理，推理之前都是空白」**。
> 这份记录同时收口上一轮（片段导出）留下的**独立待裁项** `marked = true`。

## 一、根因

`src/store.ts` 的 `mergeDrafts` 里，段级标记是**硬编码**：`const marked = true;`。
同一个函数内**单镜**走的是「真填了才改」（`if (shotFilled === 0) return shot;` 之后才打 `draftSource`），
**段标记却无条件设置** —— 一段只要被生成写入路径**扫过**，就记「已生成」，与它有没有真产出无关。

会「扫过」整集的路径（按可能性排序）：

| # | 路径 | 说明 |
|---|---|---|
| 1 | 一键生成 / 选择集生成 | 本地路径对**整集逐段**产草稿，逐段回填 |
| 2 | **整集导出 Word / TXT** | `exportTarget` → `store.prepareForExport` 对整集每一段跑一遍生成再回填 |
| 3 | 重新生成本 P | 只扫本段 —— 唯一不污染整集的路径（片段导出亦已绕开 `prepareForExport`） |

老大的观察正好命中：**AI 依次推理是一段一段来的**，还没轮到的那一段板上本该是空白，
却因为路径 1 / 2 被刷上标记 —— 于是「没推理到的 P 也显示已生成」。

### 连带影响（比显示更重）

1. `planner.hasUserContent()` 把该字段计入「用户内容」→ 一旦整集被误标，**解析口径升级后不再自动重建分集**，
   只弹 `stale` 提示，本该自愈的旧存档停在旧口径；
2. `repair.repairEpisode()` 的段标记**一直是诚实派生**（`shots.some((shot) => !!shot.draftSource)`）——
   同一个字段两套口径，迟早对不上（回填层 vs 修复层）。

## 二、修法：把「已生成」变成**派生值**（单源判据）

新增 `src/core/model.ts` 的 `isSegmentGenerated(segment)`：**本段至少一镜带 `draftSource`**
（本地规则 / AI / 人工三态在**真正写入字段**时都会打标）。

读这一处的**五方**（不得各自判断）：

| 读点 | 用途 |
|---|---|
| `store.mergeDrafts` | 回填后重算并落盘（删掉硬编码） |
| `repair.repairEpisode` | 重建后重算（原是内联同义判据，改为共用） |
| `validator` | `DIRECTOR_UNCONFIRMED` 的复核文案 |
| `planner.hasUserContent` | 该段是否已属「用户内容」（修掉上面那条连带影响） |
| `panes/DirectorPane.tsx` | P 索引条「已生成」标 + 面板计数 |

`Segment.directorGenerated` 字段**保留**（写入侧仍落盘、旧存档照旧解析），
但它只是该判据的落盘副本 —— 任何判定都不得直接读它（契约测试对导演板加了负向锁）。

### 计数口径同时收紧

`GenerationResult.segments` 由「这一批扫过几段」改为「**本次由未生成变为已生成的段数**」，
界面话术（「已标记 N 段导演决策已生成」）直接用它，故重复生成不再一直报数。
「一键生成」的本集本地路径改走 `applyGenerationBatch` **一次批量写入**：既省掉 N 段各自一次落盘，
也让这个数拿得准（原来是逐段 `applyGenerated`，拿不到段数）。

### 为什么不需要迁移存量存档

标记已是**派生值**：老存档一打开，显示、校验、`hasUserContent` 读的都是派生结果，
里面那份旧布尔（幻影标记）不再被读；下一次生成/修复写入时会被**就地改写为派生值**。
「未推理到却挂标」的段因此在界面上立即回到未生成，不需要任何一次性迁移动作。

## 五、边界（本轮**未做**，待老大裁定）

- **整集导出仍会「顺带补齐」整集**：`prepareForExport` 的既有行为没动 —— 补齐即**真写入**，
  按派生判据这些段确实变成已生成。若老大要的是「**只有我点了生成才算**」，
  需要给 `applyGenerationBatch` 加一个 `markGenerated` 开关、由导出侧传 `false`；
  本轮未做（超出截图诉求，且会改变导出前自动补字段的既有表现）。
- 存量存档里 `directorGenerated` 与派生值不一致的旧布尔，**不做一次性迁移**：
  它不再被读，下次生成/修复落盘时自然改写（见 §二末）。

## 六、本条与上一轮的关系

`99_过程归档/2026-10-06_片段导出实施记录.md` §二把 `marked = true` 列为**独立待裁项**，
并刻意让片段导出绕开 `prepareForExport`。本轮把该待裁项**收口**：判据改为派生后，
片段导出继续绕开 `prepareForExport` 的理由由「避免刷标记」变为
「**避免改动别的段的内容**」（那个函数会补齐整集字段），e2e 的防回流断言保持有效。
