# 剧本拆分工作台完整技术方案 v1.0

状态：初版技术基线；当前只实现 MiniMax H3，平台模块保留后续接入 Seedance、Wan 等目标平台的能力。

## 1. 产品定位

本项目是 Windows 本地桌面工具，将原剧本拆分为连续的剧情段落，并按照版本化分镜骨架生成完整分镜脚本：

```text
原剧本
  -> 剧本结构解析
  -> 剧情节拍与段落拆分
  -> 导演化分镜数据
  -> MiniMax H3 分镜脚本编译
  -> TXT / Word / JSON 导出
```

核心交付物是按照固定骨架生成的可审阅、可修改、可复现的分镜脚本，不是一次性生成的自由文本。

## 2. 技术选型

| 层 | 技术 | 责任 |
|---|---|---|
| 桌面框架 | Electron | Windows 窗口、本地文件、更新和系统集成 |
| 前端 | React + TypeScript | 剧本、拆段、分镜和 Skill 管理界面 |
| 构建 | Vite | 开发和生产构建 |
| 状态管理 | Zustand | 编辑状态、任务状态和界面状态 |
| UI | Ant Design 或 Mantine | 表格、表单、树、抽屉和校验提示 |
| 数据库 | SQLite | 项目、版本、规则和导出记录 |
| 数据访问 | Drizzle ORM | 数据库访问和迁移 |
| 运行时校验 | Zod | IPC、Skill manifest 和中间数据校验 |
| 导出 | 纯文本 TXT、docx | 分镜脚本交付 |
| 测试 | Vitest + Playwright | 单元、集成和界面流程测试 |
| 打包更新 | electron-builder | 安装包、签名和分阶段更新 |

首期不引入 Python、云数据库、Redis 或微服务。只有在确实需要本地视觉模型时，才增加受监管的 Worker。

## 4. 数据和编译分层

### 4.1 核心剧本层

- 导入 TXT、Markdown，后续支持 DOCX
- 识别场次、人物、说话人、台词、动作和环境描写
- 保存原文位置和原稿版本
- 原台词逐字保护

### 4.2 导演数据层

保存通用的拍摄意图，不出现平台标签：

- 剧情目的和主要动作链
- 关系变化和信息落点
- 人物站位、景别、构图和运镜
- 光线、表演、声音和镜头衔接

### 4.3 通用中间数据层

核心只定义跨平台的导演中间数据和能力接口，不定义平台专属正文骨架。各 Skill 和平台模块可以在中间数据上增加自己的字段、规则和编译结果。

### 4.4 平台层

平台模块把同一份导演数据编译为目标平台格式。当前只实现 `minimax-h3`，未来新增 `seedance`、`wan` 时不修改剧本解析和导演数据。

## 5. 内置 Skill 模块

仓库已有 Skill 在开发阶段转换为内置模块和版本快照；用户运行软件时不依赖外部仓库路径。

内容类型是 Skill 选择的一级分类，严格对应仓库 `02_编剧双轨` 下的四类目录：

```text
contentType
├─ short-drama  短剧
├─ mid-drama    中剧
├─ long-drama   长剧
└─ film         电影
```

用户先选择内容类型，再加载该类型的专用编剧/导演配置；跨类型的导演意图、表演、质检和 MiniMax H3 平台模块作为公共能力叠加。类型模块不能互相混用，切换类型只影响新建或明确迁移的项目。

```text
类型 Skill
├─ short-drama/
│  ├─ short-drama-factory
│  └─ short-drama-director
├─ mid-drama/
│  └─ ai-manhua-mid-drama-rebuild
├─ long-drama/
│  └─ ai-manhua-long-drama-screenplay
└─ film/
   └─ ai-manhua-film-screenplay

公共 Skill
├─ ai-manhua-screenplay-comprehensive
├─ ai-manhua-director-thinking
├─ ai-manhua-emotion-clip
├─ deepwhite-shotlist-builder-zh-user
├─ design-fight-videos
├─ ai-manhua-storyboard-qa
└─ minimax-h3-video-prompt
```

每个 Skill 通过统一接口接入：

```text
SkillModule
├─ manifest()
├─ registerSchema()
├─ parse()
├─ segment()
├─ generateShots()
├─ validate()
├─ compile()
└─ migrate()
```

仓库 Skill 是来源正本，不在运行时动态读取。转换结果必须记录来源路径、版本和 SHA-256，规则变化通过新模块版本发布。

## 6. MiniMax H3 模块

初版只启用 MiniMax H3：

```text
minimax-h3
├─ dialogue/       文戏切段、对白容量、声线和文戏编译
├─ action/         武戏攻防、装备能力和动作编译
├─ skeleton/        H3 专属“标题时长 + 14 条正文”骨架
├─ compiler/       H3 提示词及固定尾部编译
├─ validator/      H3 字段和平台限制校验
└─ exporter/       H3 复制稿导出
```

14 字段正文骨架只属于 `minimax-h3` 模块，不属于核心层、通用导演模块或未来其他平台。H3 专属标签和字段只存在于 H3 模块及其导出结果，不污染通用导演数据。

## 7. 按四类剧型接入导演与分镜 Skill

导演模块不另造一套平行分类，而是以“短剧、中剧、长剧、电影”作为一级路由，以仓库 Skill ID 作为模块正本；功能子模块只作为模块内部实现。

| 内容类型 | 仓库分类/模块 ID | 负责内容 | 当前状态 |
|---|---|---|---|
| 短剧 | `short-drama-factory`（L2c）、`short-drama-director` | 爆点、节奏、短剧结构和短剧导演决策 | 首期接入 |
| 中剧 | `ai-manhua-mid-drama-rebuild`（L2d） | 中剧重构、场次节奏和关系推进 | 首期接入 |
| 长剧 | `ai-manhua-long-drama-screenplay`（L2e） | 长线人物弧、集级结构和连续叙事 | 首期接入 |
| 电影 | `ai-manhua-film-screenplay`（L2f） | 电影叙事、单片结构和镜头节奏 | 首期接入 |
| 跨四类 | `ai-manhua-screenplay-comprehensive`（L2b） | 原稿结构、场次、台词和动作落稿 | 首期接入 |
| 跨四类 | `ai-manhua-director-thinking`（L3·导演意图锚） | 导演意图、空间/情绪双轴、视听决策和镜头前置 | 首期接入 |
| 跨四类 | `ai-manhua-emotion-clip`（L3） | 微表情、表演节奏、倾听反应和情绪动作 | 首期接入 |
| 跨四类 | `deepwhite-shotlist-builder-zh-user`（L3b） | 通用镜头清单和导演数据落地 | 首期接入 |
| 跨四类 | `design-fight-videos`（L3） | 阵型、攻防、动作因果和武戏调度 | H3 武戏前置能力 |
| 跨四类 | `ai-manhua-storyboard-qa`（L4 交付闸门） | 分镜质量、连续性、字段和交付阻断 | 首期接入 |
| 跨四类 | `minimax-h3-video-prompt`（L3） | H3 文戏/武戏规则、提示词和平台导出 | 当前唯一平台模块 |

仓库分类与功能子模块的关系如下：

```text
ai-manhua-director-thinking
├─ space-axis       空间、站位和180度轴线
├─ shot-language    景别、构图、焦距和运镜
├─ sound-transition 声音桥接和镜头衔接
└─ continuity       跨镜头导演连续性

ai-manhua-emotion-clip
└─ performance      微表情、倾听反应和动作可读性

ai-manhua-storyboard-qa
└─ delivery-gate    质检、阻断、复核和交付报告
```

这些模块只生成或校验通用导演中间数据，不能输出 H3 的 14 字段正文。H3 模块调用它们的结果，再编译自己的骨架。仓库中的 L5 静态视觉模块（例如 `film-shot-director`）不属于当前剧本拆分链路，除非后续增加视觉资产或静态关键帧功能，否则不加载。

## 8. Skill 可拆卸、可更新、可回滚

安装包中内置 Skill，运行时由 Skill 管理器加载：

```text
resources/skills/
├─ short-drama/short-drama-factory/2.1.0/
├─ short-drama/short-drama-director/unversioned/
├─ mid-drama/ai-manhua-mid-drama-rebuild/1.0.0/
├─ long-drama/ai-manhua-long-drama-screenplay/1.0.0/
├─ film/ai-manhua-film-screenplay/1.0.0/
├─ ai-manhua-screenplay-comprehensive/2.6.0/
├─ ai-manhua-director-thinking/3.8.0/
├─ ai-manhua-emotion-clip/1.0.1/
├─ deepwhite-shotlist-builder-zh-user/2.7.0/
├─ design-fight-videos/3.7.0/
├─ ai-manhua-storyboard-qa/1.5.0/
└─ minimax-h3-video-prompt/2.1.0/
```

每个模块提供 manifest：

```json
{
  "id": "minimax-h3-video-prompt",
  "version": "2.1.0",
  "apiVersion": "1",
  "dependencies": [
    "ai-manhua-director-thinking@^3.8.0",
    "ai-manhua-storyboard-qa@^1.5.0"
  ],
  "sourceSha256": "...",
  "capabilities": ["dialogue.segment", "h3.compile", "h3.validate"]
}
```

支持启用、禁用、卸载、安装新版本、回滚和依赖查看。卸载模块不删除原剧本、项目数据或历史导出。

更新流程：

```text
安装新版本 -> 签名与哈希校验 -> 依赖检查 -> 自动测试
-> 新旧规则差异预览 -> 用户确认启用 -> 失败自动回滚
```

已有项目锁定原版本，不因软件升级自动改变结果。仍被历史项目使用的版本保留只读缓存，保证项目可重新打开和导出。

## 10. AI 接入

AI 是可选能力，不是软件启动条件：

```text
本地规则生成结构 -> 可选 AI 补写镜头语言 -> 人工确认 -> 固定骨架编译
```

通过适配器接入：

```text
AiProvider
├─ LocalRuleProvider
├─ MiniMaxProvider
├─ OpenAICompatibleProvider
└─ LocalModelProvider
```

未配置 API Key 时仍可完成导入、拆段、编辑、校验和导出。AI 不能覆盖已锁定字段。

## 11. 校验与导出

程序确定性阻断：

- 每段时长为 15 秒
- 镜头时长合计为 15 秒
- 14 字段完整且顺序正确
- 镜头编号连续
- 原台词未被擅改
- Skill、骨架和平台版本兼容
- 同一快照重复导出结果一致

建议复核：动作负载、镜头过密、空间跳变、衔接不清、导演意图不足。

导出格式：

```text
TXT：纯文本分镜脚本
Word：正式交付
JSON：机器处理和版本归档
```

## 12. 本地文件与稳定性

```text
项目目录/
├─ project.db
├─ backups/
├─ exports/
├─ snapshots/
├─ logs/
└─ cache/
```

- SQLite 只由主进程写入
- 自动保存和重大修改快照
- 临时文件写入后原子替换
- 数据库迁移前自动备份
- 导出前保存快照和内部质检结果；TXT/Word 成品只包含分镜脚本
- 启动时执行数据库与 Skill 自检

Electron 安全约束：`nodeIntegration: false`、`contextIsolation: true`、`sandbox: true`。渲染层只能通过类型化 IPC 访问文件和数据库。

## 13. 测试体系

### 单元测试

剧本解析、台词保护、段落拆分、时长计算、14 字段、H3 编译器、Skill 依赖和数据迁移。

### 集成测试

导入到导出完整流程、Skill 启用/禁用/卸载、更新回滚、历史项目打开、重复导出一致性。

### 界面测试

用 Playwright 覆盖新建项目、导入剧本、修改和锁定字段、切换 Skill、导出以及重启恢复。

## 14. 实施阶段

### 阶段一：核心闭环

Electron 框架、项目管理、TXT/Markdown 导入、剧本解析、15 秒拆段、14 字段分镜和 TXT/Word 导出。

### 阶段二：Skill 系统

Skill manifest、内置模块加载、通用编剧 Skill、导演 Skill、MiniMax H3 文戏和武戏模块、项目版本锁定。

### 阶段三：稳定性

SQLite、自动备份、快照、数据迁移、Skill 更新/回滚、完整测试和 Windows 安装包。

### 阶段四：AI 增强

MiniMax API、OpenAI 兼容接口、本地模型接口、AI 辅助补写和差异确认。

### 阶段五：平台扩展

增加 Seedance、Wan 等平台模块和多平台导出，不改核心剧本与导演数据。

## 15. 范围边界

初版不包含视觉资产管理、视频生成、自动发布和团队协作。MiniMax H3 是当前唯一实际平台；Seedance、Wan 只保留模块接口，不提前实现平台规则。

## 16. 最终技术定案

采用 **Electron + React + TypeScript + SQLite + 内置可拆卸 Skill + 版本化分镜骨架 + MiniMax H3 平台模块**。

核心数据描述通用导演意图，平台模块负责目标平台编译；Skill、骨架、规则和导出结果全部版本化，保证后续更新可控、历史项目可复现、未来平台可扩展。
