## 2. 关键实现口径

1. **一本多集**：`Project.schemaVersion = 2`，结构为 `episodes[] + activeEpisodeId`；集内自带 `scenes / beats / segments / images`。`Episode.sourceRange` 记录该集在整本中的字符范围，供校验用该集文本重建比对。
2. **分集识别**：`parser.matchEpisodeMarker` 为唯一判定口径，`episodes.ts` 与 `parser.ts` 共用，避免双正则漂移。识别不到集标 → 整本单集 + `EPISODE_SPLIT_UNVERIFIED`，不静默硬切。
3. **迁移**：`migrateProject` 先试 v2，失败再按 v1 schema 解析并包装为单集 v2（`splitVerified = true`）。启动时读取顺序 = IndexedDB → v1 localStorage 兜底 → 无存档。
4. **本地引擎 A**：`classifyKind`（路径关键词 > 文件名关键词 > 画幅比例）、`extractSubject`（文件名主干去噪后比对说话人 / 场景名册）、`analyzePixels`（主色 top3 / 亮度 / 饱和度 / 色温 / 光源方位 / 室内外推断）。全部为纯函数，输入 RGBA 缓冲即可单测，不依赖 DOM。
5. **三级置信度匹配**：高（唯一命中）自动绑定、中（多候选）标黄待复核、低（未命中或道具图）进未分配区；每段 6 张上限在**绑定**期生效，溢出显式登记 `overflow` 并标「已入库未绑定」。
6. **一键生成**：`generateEpisodeDrafts` 逐段逐镜输出 10 条字段（`generatedKeys`），站位在集内逐镜承接；衔接取自 11 项合规池，`sanitizeTransition` 对禁词做本地拦截。写入侧 `applyGenerated` 只补空白，`overwrite` 由界面显式勾选。
7. **AI 通道**：`shotFieldsSchema.strict()` 只接受 10 个键，出现 ①②④⑫ 直接判不合格；镜头数量与 `shotId` 一一比对；⑭ 命中转场禁词即抛错 → 上层回退本地结果并提示。密钥仅存内存，不入快照。
8. **四项新增闸门**：`SHOT_DURATION_MAX`（>12s 阻断）、`TRANSITION_FORBIDDEN`（阻断）、`AUTO_MATCH_LOW_CONFIDENCE`（建议复核）、`EPISODE_SPLIT_UNVERIFIED`（建议复核）。

## 3. 顺手修复的既有缺陷

1. `electron/main.ts` 在 ESM 主进程中使用命名导入 `import { app, BrowserWindow } from 'electron'`，运行时会解析到 `node_modules/electron` 而报「does not provide an export named 'BrowserWindow'」。已改为 `createRequire(import.meta.url)` 取内置模块（类型仍由 `import type * as Electron` 保证）。此前 `desktop.spec.ts` 从未真正通过。
2. `tests/e2e/desktop.spec.ts` 未隔离 `user-data-dir`，且未排除外层注入的 `ELECTRON_RUN_AS_NODE`（该变量会让 Electron 退化为纯 Node，无法建窗）。已改为注入独立 profile 并过滤该变量。
3. `.project-controls` 行内元素不换行，390px 视口下横向溢出 100px；`.episode-note` 长文本 `nowrap` 撑破布局。已改为可换行 + `min-width: 0`。

## 5. 剩余边界

1. **本地无法产出外观描述**：本地只给图类、主体与光影色彩。① ② 的具象外观仍依赖人工文字设定或 AI 增强，与方案第 16 节一致。
2. **纯视觉 / 命名匹配不保证全对**：同一角色跨多场、相似场景易混；中置信度标黄层必须保留人工复核，不做全静默绑定。
3. **参考图存储取舍（与方案第 13 节的偏差，待裁定）**：方案要求参考图以 Blob 存入 IndexedDB、项目数据只存哈希与摘要、不内嵌 base64 预览。本次实现仍把最长边 1024 / JPEG q0.74 的压缩预览保留在 `ReferenceImage.dataUrl`，理由是：IndexedDB 已解除容量瓶颈；本地图像分析需要直接取像素；界面预览需要同步可用，分离会增加异步链路与失败面。如需严格执行 Blob 分离，建议单独立项，届时同步调整 `imageSchema` 与迁移路径。
4. **规则分镜的审美上限**：规则引擎保证合规与一致性，不保证导演级创造力，追求更高表达需启用 AI 增强或人工介入。
5. 分集切点当前支持人工核对与整体重新规划，**逐切点微调**（拖动单个切点）尚未实现。
