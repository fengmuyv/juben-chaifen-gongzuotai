# 2026-10-05 参考图图类裁决修复与 ① 人物描述注入诊断记录

## 一、问题（老大原话）

> 为什么本地一键生成在人物图描述已有的情况下，导出的分镜文档里没有相应分镜出现的人物的相应的描述

## 二、诊断：先排除导出层

`App.tsx` 导演板读数与 `core/word.ts` 的 `writeWord` **同源**调 `skeleton.values()` —— 导出侧没有任何独立的字段逻辑。
所以这不是「导出丢字段」，而是**数据层从来没注入**：界面上同一个位置也是空的（显示「等待确认」，极易与「未生成」混淆）。

① 人物参考图的描述，取值链只有一条：

```
project.assets（kind = character ＋ confirmed ＋ 有描述）
  → 自动匹配 matchImages → 段绑定 segment.imageIds
  → values() 拼接 → 界面与导出
```

任一环断，① 就是空行，而 Word 里就是空字段。

## 三、实测证据（临时探针跑真代码，跑完即删，工作区保持干净）

用 `sample` 剧本（林夏 / 陈默，两场）+ 已确认的人物描述：

| 探针 | 结果 |
|---|---|
| `林夏.png`（导入到「人物」分类） | `classifyKind` 判 **prop**（reason：无关键词与画幅信息）→ `matchImages` 返回「道具图不自动匹配段落」→ **段 = []** → ① 空 |
| `林夏_人物.png`（仅改名） | 命中 → 绑定 P01/P04 → ① 有描述 |
| 段 P02 / P03 | 每镜入画均为「林夏、陈默」，但**两段无人说话** → 段绑定为空 → ① 三镜全空 |
| P01 的 SC02 | 只入画陈默，① 却注入两人描述（多注入） |
| `confirmed = false` 的图 | 照样被绑段（`mergeMatches` 不看 confirmed），但 `values()` 过滤掉 → 且 `store.updateImage` **编辑即重置 confirmed** → ① 立刻空 |

## 四、四条根因（按严重度）

- **A 结构性**：① 注入粒度 = **段**（`segment.imageIds`），判据 = **本段有没有台词**，不是「本镜是否入画」。镜级识别（`sourceFieldsForShot().subjects`）早已存在，两套**未桥接** → 漏注入（无人说话的段）+ 多注入（一人镜写多人）。
- **B 高频触发**：匹配裁决用**分析层按文件名猜的 `kindGuess`**，而非用户导入时明确选的 `image.kind`；且 `analyzeWithStats` 不把宽高传进 `classifyKind` → 画幅兜底分支**永不可达**，无图类关键词的文件名一律判 prop。`extractSubject` 明明 high 命中角色名，却被 kind 分支提前 return 掉。
- **C 门槛不可见**：`image.confirmed` 是硬门槛，而 `CHARACTER_ANCHOR` 分级为 **warning，不阻断导出** → ① 空也能一路导出成功，无拦截提示。
- **D 名册太窄**：匹配名册只有说话人（`buildRoster` → `beat.dialogue.speaker`）；纯动作戏、从不说话、泛称（庄稼汉子）角色除「全集单角色兜底」外全进未分配区。

## 五、本轮落地：只修 B（老大选定的范围）

**改动 1 · `src/core/match.ts`** —— 图类裁决改为**以导入时选择的分类为准**：

- `const { kindGuess, subject } = analysis;` → `const { subject } = analysis;` ＋ `const kind = image.kind;`
- `if (kindGuess === 'prop')` → `if (kind === 'prop')`；`if (kindGuess === 'character')` → `if (kind === 'character')`
- 函数头注释记入缺陷来龙去脉（为何不能用文件名判图类）。

**改动 2 · `src/App.tsx` · `renderAsset`** —— 提示语义对齐：

- 新增 `kindHint`：猜测与所选分类**一致**时沿用原文案；**不一致**时显示「文件名疑似 X · 仅提示，匹配按所选分类」。
- 否则会出现「图摆在人物区、副标题却写判为道具」的自相矛盾。

**未改**：匹配宽严一律不动 —— 用户明确归到「道具」的图仍不自动匹配；三级置信度、每段 6 张上限、未分配区口径不变。改的是**裁决来源**，不是放宽。

## 六、测试护栏

`tests/unit/workbench.test.ts` 新增 `matches by the importing category, not by the filename guess`：

1. 前提护栏：断言 `林夏.png` 的 `kindGuess === 'prop'` 且 `subject === '甲'` —— 把「旧口径必挂」的前提钉死，防止将来 `classifyKind` 变了让用例失去意义；
2. 正向：归到「人物」的同名图**必须绑上**（`reason` 含「角色「甲」」）；
3. 防回流：归到「道具」的同名图仍 `segmentIds === []`；
4. 分类真在起作用：同名图归到「场景」按场景名册匹配，落到另一段；
5. 与 ① 打通：段上绑定已确认人物图后，`values(project, shot)[0]` 必须含该描述。
