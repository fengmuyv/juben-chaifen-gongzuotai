## 一、核验：问题不在「写死剧本名」，而在「按样本枚举词表」

### 1.1 先排除「硬编码剧本名」

全仓 grep（`猫大夫` / `快乐处方` / `灰灰` / `城市广场` / `苏清苒` 等）结论：

- **源码里没有任何剧本名或人物名进入判定逻辑**；
- 只有两处**注释举例**：`src/core/parser.ts:45`（`### 第七集` / 《猫大夫的快乐处方》）、
  `src/platforms/minimax-h3/director.ts:302`（`苏清苒猛地转身`）；
- 测试文件里的剧本名属正常 fixture。

所以「针对某一剧本」不是以硬编码的形式存在的。

### 1.2 真正的形式：四张枚举词表

全部集中在 `src/core/parser.ts`：

| 词表 | 位置 | 条数 | 性质 |
|---|---|---|---|
| `briefHeadings` | 非正文块标签 | ~90 | 决定「哪些标题非正文」 |
| `castHeadings` | 人物表标题 | 10 | 哪些块内人名进名册 |
| `subjectStopwords` | 名词停用 | ~90 | 排除「被误当人名的词」 |
| `roleSpeaker` | 角色称谓 | ~60 | `大爷` / `妇女` / `汉子` / `村民`… |

### 1.3 实测方法（可复用，零仓库写入）

1. **产品内置通用闸门**：`npm run audit:script -- "<剧本路径>"` → `tests/audit/script.audit.test.ts`。
2. **纯解析探针**：`node --experimental-strip-types <探针.mjs>`，用 `file:///E:/…` 绝对 URL
   直接 import `src/core/parser.ts`（该文件只有 `import type`，无需打包即可运行），
   打印集标命中 / 场次 / 名册 / 节拍明细。

样本：`E:\wb_temp\parser-general-probe.md`（**虚构剧本，非任何真实剧目**）。

### 1.4 实测结果（改造前）

```
名册 4：["订单","库存","沈砚","管家"]           ← 账目名词污染名册
节拍 15：作品信息 / 台词统计 / 沈砚 34 / 林可 28 / 管家 6 / 出场人物 /
        沈砚，28 岁… / 林可，26 岁… / S01 调度中心 夜 内 / …
场次 1：scene-1「未标注场次」                    ← 一个场次都没认出来
```

四项失败：

1. **名册被文档层名词污染** —— `订单：2400 单待分配。` 被当成可信台词。
2. **主要人物 `林可` 整条丢失** —— 人物表标题写作 `出场人物`（不在词表里），整块无人识别，
   而她在这份样例里没有台词可佐证。
3. **未枚举标签整块泄漏** —— `作品信息` / `台词统计` / `出场人物` 三处 → 8 条垃圾节拍。
4. **场次识别漏** —— `S01 调度中心 夜 内` 未被识为场次；**真实反例**是老大那边的
   `7-1 城市广场 日 外`（集-场编号 + 时空标记）。

**根因一句话**：判据是「**枚举该丢的词**」，而剧本是无穷的 —— 词表永远追不上新剧本。

## 二、★ 自我更正：`briefHeadings` 尾部长尾不是「样本垃圾」

上一轮清单里，我把 `六道护栏` / `三条验收断言` / `路A补写说明` / `全剧实测` / `源脚本系列` /
`定稿状态` 判为「某版文档的一次性产物」，主张删掉。**这是错的。**

证据：

- `tests/unit/workbench.test.ts` 有用例**锁死**这组行为
  （`三、路 A 补写说明（画面密度）` / `动因：` / `做法：` / `六道护栏（全部通过）：` / `三条验收断言（全部通过）：`）；
- `.workbuddy/memory/2026-10-01.md` 记载这是当日修的 **P0「非正文块提前解屏」**，修后「泄漏节拍 → 0」。

即：这批判据是**老大定稿稿前言统计表与附录「补写说明」格式的契约**，不是垃圾。

**结论**：T1 改为**纯增量** —— 通用化靠**增判据**，不靠删契约。契约脚本里加了反向护栏，
防未来误删。

## 三、四项改造

### T2 · 说话人可信度（构词 + 值形态 + 两遍扫描）

| 判据 | 内容 | 治什么 |
|---|---|---|
| `nonPersonNounTail` | 汉语人名不会以 `额/量/率/账/帐/单/号/码/证/照/片/卡/屏/盘/档/案/库/存/据/录/件/款/键/费/税/价/息/表` 收尾 | `订单` / `库存` / `总额` / `账号` / `密码` / `照片` / `文件`… |
| `looksNumericValue` | 值以数字 / 货币符号 / 数量短语开头 → 该行是账目，不是话 | `余额：2,430。` / `订单：2400 单待分配。` |
| 两遍扫描回填 | `订单：2400 单待分配。` 与 `苏清苒：3000 块我出。` 在**第一遍长得一样**；名册攒齐后第二遍才分得开 | 救回「值以数字开头的真台词」 |

第二遍实现要点：第一遍把「像人名 + 值以数字开头」的行记入 `pending`（附 beat 下标），
整篇扫完后**倒序**替换（只有更靠后的下标被改动，先前下标仍有效），末尾统一重排 `beat-N`。
已确证姓名（在 `cast` 里）**无条件放行** —— 真台词写数字开头也不会被误降级。

### T1 · 非正文块（前言区 + 块形态结构印证）

`briefHeadings` 保留不动，新增三条判据：

1. `isBareHeadingLine` —— 裸标题行：短(≤8)、无数字、无空白、无 `，。：` 等取值分隔符。
2. `looksMetadataShaped` —— 元数据形态：表格行（含 `｜` 或含数字单元）或「短标签 + 短值」的
   `标签：值` 行。**关键区分是值不是句子** —— 文档层的值是短词组（`夜航西飞` / `12` / `90 秒`），
   正文叙述行的值是句子（`门外传来脚步声：很轻。`）。
3. `documentBlockEnd` —— 块内非空行 ≥2 行且**逐行**都是元数据形态才算文档层；任一行不是、
   或是集标 / 场次标题 / 台词行 / 另一个裸标题 → 立即否决。

**位置闸门**：只在**前言区**（本集文本里首个集标**之前**）生效，且**整篇必须有集标**才启用。
正文区一律不猜（宁可不丢，不可错吞）；一本连集标都没有的稿子不猜
（已有 `EPISODE_SPLIT_UNVERIFIED` 闸门提示人工核对）。

命中后用**跳行**吞掉块，不复用 `skip` 态 —— 块的确切结束行已算出，不必让「解屏」去兜。

### T4 · 人物表登记（前言区结构判据 + 顿号名单行）

1. `castBlockEnd` —— 前言区人物表块：块内非空行 ≥2 行、逐行都是「短词 + 分隔符 + 描述」
   （`castEntry`）且短词过 `isCastName`。两条否决：任一行含句末标点（那是句子不是条目）；
   描述部是裸数字（`沈砚 34` 是统计表行，交给 `documentBlockEnd` 当元数据处理）。
2. `rosterNamesOf` —— 顿号名单行：值是顿号分隔、且每段都像人名（或命中角色称谓）→ 名单不是台词。
   登记时再过一道 `isCastName`（`路人若干` 是计数不是人：**形态成立但不登记**）。
   前言区整行不进节拍；正文区保守保留原文件拍（一个字不丢）。
3. `countTail`（`若干` / `数名` / `余名` / `多名`）—— 计数段不是人物名。
4. 前言区优先级：**先判人物表、再判通用文档块**（人物表是前言区最该被认出的一块）。

### T3 · 场次标题（结构特征）

旧口径只认 6 种写法。新口径按两类通用特征：

- `sceneExplicit` —— `# 标题` / `INT.` / `EXT.`；
- `sceneNumbered` —— `第N场` / `场次N` / `场景N` / `场面N` / `序场` / `过场` / `S01` / `SC01`；
- `sceneNumberPrefix` —— `7-1` / `1.` / `1、`（集-场编号）；
- `sceneTimeMark` + `scenePlaceMark` —— 行内同时有时间词（日/夜/黄昏…）与**独立成词**的「内」/「外」。
  二者必须成对出现，或配一个纯数字编号 / 短行（≤12 字）—— 否则正文里「夜里」「外面」会误判。

## 六、已知边界（未做，待裁定）

- **附录区**：单集切片里无法从位置判断「末尾是附录」。老大定稿稿格式的附录标签由
  `briefHeadings` 覆盖；**别人剧本**的未枚举附录标题仍可能泄漏。要覆盖需引入风险更高的
  块形态判据（正文中段的猜判），当前按「宁可不丢」不做。
- **`subjectStopwords` 未删**：其中 `门上` / `桌上` / `地上` 等与已有的 `locativeTail` 规则重复，
  属冗余但不致害；未删是为把风险面收在本轮之内。构词判据 `nonPersonNounTail` 已能覆盖其主要职责。
- **场次粒度**：老大 2026-10-05 裁定「场次先不管，先只按集来」—— 本轮只让场次**认得出来**
  （进 `scenes` 表），未让 `集-场` 编号参与分集切点。
