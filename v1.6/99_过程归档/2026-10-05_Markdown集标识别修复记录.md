# 2026-10-05 Markdown 井号集标识别修复记录

## 一、反馈与症状

老大贴出《猫大夫的快乐处方》工作台截图并发问「怎么识别的」。图上三处明确异常：

- 分集浮层里**只有一集「第01集」**（`491 段`）；
- 右栏 **`24098 项阻断`**（本段 57 项）；
- 问题清单里出现「**场次或节拍与原稿不一致**」「原台词、说话人、顺序或原文位置被修改或遗漏」。

稿件形态（截图可见）：**集标写成 Markdown 标题** `### 第七集`，场次写成「集-场」编号 `7-1 城市广场 日 外`。

## 二、只读核验（根因）

`src/core/parser.ts` 的分集标记正本：

```js
const episodeCapture = /^\s*(?:第\s*([0-9]{1,4}|[零一二三四五六七八九十百千两]{1,8})\s*[集话章]|(?:EP|EPISODE)\s*([0-9]{1,4}))\s*(?:[：:、.．\-—]\s*)?(.*)$/iu;
```

**行首只允许空白** —— 遇到 Markdown 的 `#` 直接失配。于是：

1. `episodeHeadingOf('### 第七集')` 恒为 `null`；
2. `splitEpisodes` 的 `detected.length === 0` → 走兜底分支，返回**整本单集**：`label = 第01集`、`recognized: false`；
3. 整本按一集拆段 → **491 段**；每段每镜全部走生成与校验 → 阻断按段镜数线性放大 → **24098 项**。

**连带根因**：`isSceneHeading` 的正则首个分支就是 `#{1,6}\s+`：

```js
/^(?:#{1,6}\s+|第[^\s]{1,12}场|场次\s*\d|场景\s*\d|(?:内|外)[.． /-]|INT\.|EXT\.)/iu
```

所以 `### 第七集` 还会先被当成**场次标题**。集标与井号场次**同形**，靠内容区分 —— 判定顺序就成了硬约束。

## 三、复现（测试先红）

新增 `describe('分集：Markdown 井号集标（老大《猫大夫的快乐处方》实测复现）')` 三条，首跑 3 红，其中最直接的一条实测输出：

```
expect(parsed.scenes.map((item) => item.title)).toEqual(['7-1 城市广场 日 外'])
  - Expected: [ "7-1 城市广场 日 外" ]
  + Received: [ "第七集" ]
```

**直接量到「第七集」在冒充场次**，与只读核验的推断完全一致。

## 四、修复（两处，都在 `src/core/parser.ts`）

1. **放行 Markdown 井号前缀**：`episodeCapture` 行首改为 `^\s*(?:#{1,6}\s+)?(?:第…`。
2. **集标判定提到场次判定之前**：`parseScript` 里 `if (isEpisodeMarker(trimmed)) continue;` 由「`isSceneHeading` 之后」移到「之前」，并注明理由（否则井号集标冒充场次）。

第一处解决「识别不到集标」，第二处解决「集标冒充场次」——**缺第二处，只修第一处会让集标从「不识别」变成「认成场次」**。

## 五、效果（同一份样例，修复前后）

| 口径 | 修复前 | 修复后 |
| --- | --- | --- |
| 分集 | **1 集**（第01集） | **2 集**（第07集 / 第08集） |
| 段数 | 整本 **491 段** | 3 段 / 1 段 |

## 六、场次粒度：老大裁定「场次先不管，先只按集来」

提问「要不要把 `集-场` 编号纳入合法场次形态」后，老大裁定：**「场次先不管，先只按集来」**。

- **不扩** `isSceneHeading` 的支持范围（现状：`# 标题` / `第N场` / `场次 N` / `场景 N` / `内外.昼夜` / `INT.` / `EXT.`；归档实证既有剧稿用 `场景 3　日.内　办公室`）。
- `7-1 城市广场 日 外` 这类「集-场」编号**不纳入**。一集 = 一个大场次（`未标注场次`）。

### 6.1 该裁定下的验收实测（按「只按集」跑通）

用含 `集-场` 场次行的样例（2 集 / 5 场次）实测：

| 口径 | 修复前（集标失配） | 修复后（只按集） |
| --- | --- | --- |
| 分集 | **1 集**（第01集） | **2 集**（第07集 / 第08集） |
| 段 | 整本 **491 段** | 4 段 / 2 段 |
| 阻断 | **24098 项** | **325 项**（其中 `FIELD_REQUIRED` 264 = 未做一键生成的正常待填） |

**阻断量级已从「不可用」收敛到「正常待生成」**，这是「按集走通」的主判据。

### 6.2 残留发现项（**均与场次粒度无关**，实测有据，尚未处理）

1. **场次头行会被切成镜头**。`7-1 城市广场 日 外` 既不匹配 `isSceneHeading`、也不匹配元数据/集标 → 落成 `action` 节拍 → 被段消费。实测输出：

   ```
   ★被切成镜头  "7-1 城市广场 日 外"
   ★被切成镜头  "7-2 楼道 日 内"
   ★被切成镜头  "7-3 小区门口 夜 外"
   ```

   第07集 16 镜里 **3 镜是这种垃圾镜**。修法极小：把该形态当**标记行剔除**（不成节拍）—— **不等于做场次粒度识别**，只是「不把它当正文」。

2. **`人物：灰灰、路人若干` 被当台词**。`briefHeadings` 有「人物设定 / 人物表 / 主要人物 / 人物关系」，**没有单独的「人物」**；于是该行以说话人 `人物` 登记进**人名册**（实测 `["人物","灰灰","男人"]`），⑦站位存在写出「人物」的风险。修法极小：给 `briefHeadings` 补一个「人物」。

> 两条都按老大的范围裁定**未擅动**，等一句话。
