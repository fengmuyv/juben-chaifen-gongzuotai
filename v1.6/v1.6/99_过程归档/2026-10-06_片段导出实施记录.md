# 片段导出实施记录（2026-10-06）

> 来源：老大截图（导演板 P 索引条 + 段头行）「支持分段导出，在这个位置找一个地方加一个按键『导出当前片段』」。

## 一、需求与四条裁定

| 决策点 | 裁定 |
|---|---|
| 「片段」粒度 | **P ≡ 15 秒一段**（既成事实：`core/planner.ts` 造段即 `P01`…）。按钮放段头行，只作用于**当前选中的那一段** |
| 闸门口径 | **只按本段**：本段 error ＋ **无 `segmentId` 的集级 error**（原稿层事实类）。不被其他段拖累；但原稿层已坏时任何片段都不放行 |
| 产出格式 | **一个按钮 ＋ 同行格式下拉（Word / TXT）二选一** |
| 按钮位置 | `.segment-actions` **末尾**（「重新生成本 P」右侧），**不移动任何既有控件** |

## 二、为什么片段导出必须另起一条入口，而不是复用 `exportTarget`

整集导出的入口 `exportTarget()` 内部会调 `store.prepareForExport(episodeId)`，而它做两件事：

1. 对**整集**跑 `repairProject` 结构修复；
2. 对**整集每一段**跑 `generateEpisodeDrafts` 并 `applyGenerationBatch` 回填。

第 2 步会经由 `store.ts` 的 `mergeDrafts` 把**每一段**写成 `directorGenerated: true` —— 该函数里段级标记是 `const marked = true`（**硬编码**），**与「本段是否真的填进了字段」无关**：同一函数内单镜走的是「真填了才改」（`if (shotFilled === 0) return shot`），段标记却无条件设置。

后果就是老大观察到的那一幕：**没主动生成，P01–P14 却全挂着「已生成」**——只要发生过一次「一键生成」或**任意一次导出**，整集就被扫成已生成。

因此片段导出**刻意不接 `prepareForExport`**，改由编排层新入口 `exportSegment(segmentId, format)` 承担，闸门只做两件事：取 `validate(project, episode.id)`，过滤出「本段 error ＋ 无 `segmentId` 的集级 error」。这样既守住了原稿层的事实类闸门，又不会把别的段挂上「已生成」。

> **独立待裁项**：`marked = true` 这个语义缺陷本身（「已生成」名不副实）**未在本轮修**，属另一件事，等老大单独裁定。

## 三、改动面

| 文件 | 改动 |
|---|---|
| `src/core/model.ts` | 新增 `segmentsOf(episode, segmentId?)` —— 片段范围的**单源**取值口；段号不存在时**抛错，不静默回退整集** |
| `src/core/word.ts` | `writeWord(project, episodeId?, segmentId?)`：走 `segmentsOf` 收范围，首行随范围收敛为「作品名 集号 段号 分镜脚本」；**不传第三参时逐字不变** |
| `src/platforms/minimax-h3/compiler.ts` | `previewText` / `exportBundle` 加第三参 `segmentId`；`exportBundle` 的闸门在片段口径下按「本段 ＋ 集级」过滤 error，快照加 `segmentId` 字段 |
| `src/App.tsx` | 新增 `exportSegment(segmentId, format)` 编排入口；新增编排层 state `segmentExportFormat`（与顶栏「覆盖已有内容」同类，放内部会被「清空工作台 → 重新导入」的卸载重挂静默重置） |
| `src/panes/DirectorPane.tsx` | 段头新增格式下拉（`aria-label="片段导出格式"`）与按钮「导出当前片段」，新增 3 个 props |
| `src/styles.css` | **未改**。`.segment-actions` 已是 flex + wrap，新控件与既有「重新生成本 P」同样继承全局按钮样式，视觉自然一致 |
| 测试 | 单测 3 条（`tests/unit/workbench.test.ts`）＋ e2e 1 条（`tests/e2e/workbench.spec.ts`）＋ 契约断言 1 组（`tests/方案文档.Tests.ps1`） |

**保持不动**：`src/platforms/**` 判据、`electron/**`、`src/core/model.ts` 的 schema（零数据结构改动）。

## 四、验证证据

- `npx tsc --noEmit` → 退出码 0。
- `npx vitest run tests/unit/workbench.test.ts` → **160 passed**（原 157 ＋ 新增 3）。
  - ① 不传第三参与显式传集号，产物**逐字相同**（加能力不得动老路径）；
  - ② 片段产物只含该段的镜、首行含「集号 段号」、字段行 = 该段镜数 × 14；
  - ③ 段号无效（`P99`）时 `writeWord` 与 `exportBundle` 均**抛错**，不静默回退整集；
  - ④ 别的段写了转场禁词 → 整集口径拦、本段口径放行；本段台词被改（`DIALOGUE_PROTECTION` 无 `segmentId`）→ 本段口径也拦。
- e2e 用例「exports the current segment only…」：先只重生 P01（`.gen-tag` 计数 1）→ 片段导出 Word（文件名含 `P01`、`.docx`）→ 切 TXT 再导（`.txt`）→ **断言整集仍只有 1 个「已生成」标**。这条断言是防回流的关键：谁把片段导出接回 `exportTarget`，它立刻红。

## 五、边界与未做

- 片段导出**不触发**自动修复（`repairProject`）。若某段结构本身错乱，闸门会给出条目与跳转，由用户在全书清单里处理——与「整集导出会先自动修复」是不同取舍，刻意保留。
- 「导出当前片段」只作用于**当前选中的那一段**；批量导出多个片段（如勾选导出）未做。
- `directorGenerated` 的语义缺陷（`marked = true`）未修，见 §二 待裁项。
