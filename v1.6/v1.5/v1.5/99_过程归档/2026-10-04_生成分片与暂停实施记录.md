# 生成分片与暂停实施记录（2026-10-04）

## 由来

老大反馈：**「导入剧本后很卡」**、**「接入 ai 后一键生成改为 ai 依次推理，并且要接入暂停按键」**。

## 一、耗时归因（实测，不是推测）

临时探针 `tests/e2e/__perf.spec.ts`：379k 字 / 52 集 / 8 场 × 24 节拍，dev 构建。

| 阶段 | 修复前 | 修复后 |
| --- | --- | --- |
| 导入墙钟 | 1159 ms | ~1050 ms |
| 导入期长任务 | 5 个 / 合计 876 ms / 最大 337 ms | 5 个 / 合计 784 ms / 最大 **286 ms** |
| 导入后静置 4 秒 | — | **长任务 0 个**（无渲染循环、无残留后台计算） |
| 全部分集生成 | **单个长任务 12 798 ms**（主线程完全锁死） | 116 个分片 / 合计 16 258 ms / 最大 **517 ms** |

CDP 采样剖析（`Profiler.start` / `stop`，自耗时）给出的导入期构成：
解析层 `parser.ts` 各内部函数约 135 ms、审计（`auditEpisodeContent` 逐镜）约 115 ms、
IndexedDB 写入 `saveDraft` 43 ms、浏览器自身渲染与排版 `(program)` 383 ms、GC 44 ms。

**结论**：计算层与 docx 解析都不是瓶颈；「卡」的真正大头是**整本生成那个同步长循环**。

## 二、实施范围

`src/App.tsx`、`src/panes/SourcePane.tsx`、`src/styles.css`。

### 1. 分片让帧（`yieldToMain`）

`MessageChannel` 排一个宏任务边界让出主线程（不用 `setTimeout`：它的 4 ms 下限会让分片代价翻倍）。

### 2. 作业状态机与 `checkpoint()`

`idle / running / paused` 三态存在 `useRef` 里，`checkpoint()` 在每个分片边界被调用：

```
现读状态 → idle 则抛哨兵 jobStopped → paused 则挂起（不占 CPU）→ 让出一帧
```

状态**每次现读**，不做类型收窄缓存 —— 暂停/终止由界面按钮异步改写，收窄会读到陈旧值。

### 3. 暂停 / 继续 / 终止

进度面板新增三个按键，只在作业运行（`busy`）时出现。
暂停停在分片边界、已完成分片已落库；继续释放挂起；终止把状态置回 `idle`，
`checkpoint()` 随即抛哨兵、当前分片收尾退出。

### 4. 分批写入

`batchSize = 3` 集凑一批就用唯一写入口 `store.applyGenerationBatch` 落库一次。
分批有两个目的：① 终止时已完成批次已在库里；② 写入本身是一次同步合并 ——
实测 **8 集一批会压出约 1 秒的单次阻塞**（1008 ms），收到 3 集一批后降到 517 ms。
终止时还会把「已完成但没凑满一批」的集补写一次，推理成果不丢。

### 5. 折叠态不再全本解析

`SourcePane` 的整本识别结果改为**展开后才解析**：折叠态原本既不渲染 DOM、却照样跑一次全本
`parseScript`。条数也只在展开后给出（摘要显示「展开后统计」），
这是「折叠态不渲染 DOM」在**计算**上的同一条纪律。

## 三、验证证据

- e2e `生成作业可暂停、可继续、可终止，终止后已完成的集保留`：
  暂停后**等 React 排空再定时长条宽度必须纹丝不动**、继续后必须推进、
  终止后进度面板消失且已写入的集仍带「已生成」标记、全程无 `pageerror`。
- 渲染层 e2e 全量 14 项通过；全量单测 155 项通过；两个 tsc 工程 0 错。
- 提交：`1e789f4 perf(generation): 整本生成分片让帧并接入暂停/继续/终止 · 折叠态不再全本解析`。

## 四、排障记录（供后续复用）

- **暂停探针曾经误判**：比对「暂停点击前的标签」与「暂停 1.5 秒后的标签」得出「暂停无效」。
  真实原因是 React 批量提交让 DOM 读数滞后，不是暂停失效。
  改用 `checkpoint()` 自增计数（暂停后计数冻结在 33、不再增长）才确证暂停生效。
  固定手法：**验证暂停用计数或时长条宽度，不要用「作业自报的进度标签」**。
- **点击被 React 重渲染打断**：进度面板在生成中高频重渲染，Playwright 的普通
  `click()` 会因「元素 detached」重试并可能拖到超时。用 `click({ force: true })`。

## 五、剩余边界

- 单次最长阻塞 517 ms 来自 `mergeDrafts` 对该批全部镜头的同步合并；更细的分批会换来更多
  次整页重渲染，本轮不做。若要继续压，方向是让生成草稿直接产出终态、省掉二次合并。
- AI 逐段推理的**总时长**取决于段数 × 单次往返；52 集 × 约 128 段是上千次串行请求，
  暂停/终止只解决「可控制」，不解决「快」。
