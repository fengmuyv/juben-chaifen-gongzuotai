# 分镜脚本机器化自检与交付（Storyboard QA Gate）

## 何时用

分镜/逐秒脚本**已经写完、准备交付之前**。特别是用户提出以下任一约束时，本技能是强制闸门：

- "重复自检，无误后再交付"
- "禁止修改原剧本的台词" / "台词必须原文照录"
- "某能力的发动时机已规划完毕，禁止增添使用场景"
- "在文档头部标记都添加了哪些情节"

## 核心原则：自检必须可执行，不能是修辞

**肉眼自检 = 假自检。** 长分镜动辄 700 行、40+ 镜、20+ 句台词，人工核对必然漏。本技能的全部价值在于：把每一条"核查通过"都换成一个能跑出数字的脚本断言。

写在文档里的自检结论，**必须与脚本输出的数字逐项对应**。若文档说"22 句台词"而脚本数出 26，则文档错、脚本对。

### 轮次 3 的扩展 · 场景与空间治理层齐备性（v1.2 新增）

字段完整 ≠ 空间可用。分镜交付物还须核查**空间治理层三件套**是否齐备：

| 件 | 位置 | 内容 |
|---|---|---|
| ① 站位轴线声明 | 文档头部（半角引用块） | 场景大件方位 ＋ 机位侧 ＋ 左右锁死 ＋ 站位变更路线，**一整段** |
| ② 场景锚与站位轴线总图 | 全局设定 | **空间坐标锁／越轴禁令／机位—可见面一致性／光源链路** 四条 |
| ③ 对应校验项 | 自检章 | 站位轴线零漂移／可见面零矛盾／场景大件在位／标签口径 |

**齐备性核法（可跨集复用）**：逐节比对本集与**上一个已交付集**的同类章节，缺哪件列哪件。
实测教训：EP20 相对 EP19 **三件全缺**——这正是「用户问『分镜是不是也要重新弄一下』」的真正原因。

### 轮次 6 的扩展 · 低级转场全面禁律（v1.4 · 2026-09-24 用户令）

> **用户原话**：「衔接禁止闪黑，闪白，叠化，推，拉等低级转场」。

**禁词表（`scripts/verify.py` → `TRANSITION_KEYWORDS`，已扩表）**：
`渐黑 / 渐白 / 黑屏 / 黑场 / 白场 / 白屏 / 闪黑 / 闪白 / 叠化 / 交叉溶解 / 溶解 / 淡入 / 淡出 / 淡入淡出 / 推镜转场 / 拉镜转场 / 定格黑底`

**判读口径（两条，缺一不可）**：

1. **禁词只允许出现在否定性/说明性语境**：命中行若含 `非 / 禁止 / 替代 / 零 / 改为 / 不用 / 无` 等标记 → 视为合规说明；否则判 ⚠ 不合格。
2. **每个镜间接点必须写明衔接设计**：须出现「衔接手段 + 匹配元素」的表达，例如
   `衔接：动作接动作（水杯落桌相位匹配）`、`衔接：遮挡转场（前景衣架扫过）`、`衔接：J-Cut（下句台词先入）`。
   **没有任何衔接说明的接点 = 视为默认用了「无设计硬切」，同样判不合格。**
   **例外**：写明理由的有意图硬切（如"硬切：制造情绪顿挫"）可通过。

**合规替代池**：动作接动作 · 视线引导 · 遮挡转场 · 匹配剪辑（形状/运动/色彩/构图）· J-Cut · L-Cut · 空镜缓冲 · 同向运动顺接 · 光影变化接 · 焦点转移接。

**判读口径 3 · 遮挡转场的「峰值交接」完整性（v1.8.0 新增 · 2026-10-04）**：

- **只写手段名 = 未完成**：写「遮挡转场（前景衣架扫过）」而**无任何峰值参数** → 判 `PATCH`（要素不全，须补写后再交）。
- **四个字裸写 = 不合格**：只写「遮挡转场」而无遮挡物、无方向、无参数 → 视同「没设计」，与"无衔接说明"同档判 ⚠。
- **应补足的五要素**：**① 遮挡体进场**（遮挡物 + 比主体更近 + 方向 + 匀速擦过 + 与镜头横移同向）**② 覆盖峰值**（覆盖 ≥95% 画面 **且** 完整保持 ≥8 帧）**③ 峰值换景**（仅峰值窗口内换环境；景别机位不变、主体状态不变）**④ 同向退出**（不折返）**⑤ 落点恢复**（从原有横坐标显露 + 明确收势停稳）。
- **判定性质**：本口径为**人工/半自动核对项**（自然语言参数不在 `verify.py` 的机器断言范围内，本轮**不新增脚本断言**，避免假阳性）；判级并入轮次 6 的既有两个口径一起出结论。
- **正本**：写法规范见 `ai-manhua-director-thinking` §0.3.1；条目正本 `E:\仓库\ai漫剧\02_知识经验\学习总结\AI遮挡转场_峰值交接五层结构_学习总结_20261004.md`（源：抖音 @野生小四）。

### 轮次 10 · 分镜前置五要素齐备性（v1.4 新增 · 硬门禁）

> **用户原话**：「分镜脚本强制先导演思维构思光线，构图，人物站位，微表情和微动作，还有镜与镜之间的衔接……**后给成果**」。

**性质**：这是**顺序性门禁**，不是格式检查——它校验「稿子是不是在完成五项构思之后才写出来的」。

**逐集核对清单（缺一项即判 REWORK，禁止交付）**：

| # | 要素 | 合格判据 |
|---|---|---|
| ① | 光线 | 逐镜可见光源链路 / 方向 / 色温 / 影调 / 明暗关系，且与情绪曲线咬合 |
| ② | 构图 | 逐镜可见视线焦点 / 景别 / 景深 / 前中后层次 / 留白与头空间视线空间 |
| ③ | 人物站位 | 轴线零漂移、左右锁死、走位路线明确、机位—可见面一致 |
| ④ | 微表情与微动作 | 肌群级 + 肢体级**可执行动作**；出现「紧张地看着」类情绪形容词 = 不合格 |
| ⑤ | 镜间衔接 | 逐个接点有「衔接手段 + 匹配元素」（见轮次 6 扩展口径） |

**判级**：
- 五项齐备且逐镜可得 → `PASS`
- 个别镜头缺项但可局部补写 → `PATCH`（补写后复跑本清单）
- 整集缺失构思层（如只有画面描述无光线/站位/衔接）→ `REWORK`，退回 `ai-manhua-director-thinking` 重做前置

**上游联动**：五要素的**执行方法**在 `ai-manhua-director-thinking`（L3）§零「分镜前置硬门禁」；微表情微动作的可执行写法交 `ai-manhua-screenplay-comprehensive` / `micro-expression-annotation-system` 落标注。
表面看像"描写不够细"，实质是**整套空间治理层没有继承**，导致并肩段座位与朝向无锚、出图必歧义。

**外部资产正本对照法**（用户给出场景／人物资产图时）：

1. 把资产正本当**空间事实源**，先逐项列可确认的场景大件（方位 ＋ 材质 ＋ 陈设）；
2. 再逐镜扫 ②⑤⑥⑦ 空间类字段与之对照，落三类账：**冲突**（须改）／**缺失**（可补）／**吻合**（不动）；
3. 源稿与正本冲突处**不擅改**，先列「待补」等用户裁决；
4. 正本的**材质**信息往往能反证源稿负面词（如负面词写"茶几材质变成木质" ⇒ 茶几必为石材），可作交叉验证。

### 轮次 11 · 镜间状态继承核查（v1.5 新增 · 硬门禁）

> **触发**：用户原话「**镜与镜之间不连贯**」（2026-09-24 小红书反推分镜一役）。

**核心命题**：「⑬ 衔接」只写出手段＋匹配元素 **是不够的**。手段解决的是「怎么切」，**状态继承**解决的是「切过去之后对不对得上」。二者缺一，观感就是不连贯。

**合格写法（两处必改）**：

- **④ 站位** → `〔继承〕上镜末态 ＋〔本镜〕初态→末态`
- **⑬ 衔接** → `〔上镜末态〕→ 手段（匹配元素）→〔本镜初态〕`

**必检的六条状态链（每片立项时钉死，逐镜必须继承）**：

| # | 状态链 | 典型断裂 |
|---|---|---|
| ① | **人物高度链** | 上镜站着、下镜悬空，中间无「被托起」的交代；或悬空后直接落地 |
| ② | **巨物／道具形态链** | 上镜物件已成型，下镜又「重新拔起」——重复起势 |
| ③ | **方位与主光链** | 月亮／主光／关键大件在各镜方位不一致（原片可能是生成漂移，但**成稿必须锁一个**） |
| ④ | **机位俯仰链** | 俯仰角无动机跳变；每次变化须写明动机 |
| ⑤ | **环境状态链** | 水位／天气／光照强度／人群密度等前后不一致 |
| ⑥ | **人物姿态与手势链** | 上镜手势与下镜起始手势对不上 |

**判定**（`qa_continuity.py` 五项断言）：

- C1 每镜 ④ 含〔继承〕+〔本镜〕
- C2 非首镜 ⑬ 含「上镜末态」+「本镜初态」
- C3 方位链一致（只扫**逐镜正文字段**，跳过章节标题行，避免误报）
- C4 关键状态链完整（如高度链须出现「托离 → 悬空 → 落回」三环）
- C5 巨物无重复起势

**⚠️ 脚本自身的坑（本次踩过）**：正文切分若用 `^SC\d+`，会误切到铁律章节里以 `SC01–SC03` 开头的行 ⇒ 凭空多出空块、字段全报缺失。**镜块切分一律用 `^SC\d+【`**（标题必带全角书名号），md 侧用 `^#+\s*SC\d+【`。

**原片有断裂时的处置口径**：反推稿可**锁一个方案**保证成稿可生成，但须在状态链里**明确标注原片实况与差异**（如「原片 4.8s 在左上、8.0s 漂至右上，本稿统一锁左上；如需忠实复刻仅需回改本链与 SC05／SC09 两句」）——既保可用，又留回改依据，不掩盖事实。

### 轮次 1 的两种口径（先判口径，再选判定标准）

| 口径 | 判定标准 | 触发语 |
|---|---|---|
| A · 逐字照录 | 原剧发声单元**子串命中（去标点归一化）**，缺失/篡改 = 0 | "台词必须原文照录""禁止修改原剧本台词" |
| B · 语义锚 + 口语化 | **中文锚句零改动**（逐字命中源稿中文行）＋ 口语版英文命中 ＋ 未缩写残留 = 0 ＋ 单句词数 ≤ 上限（本项目 12 词）＋ 语气词每句 ≤1、全片 4–5 处 | "台词改为欧美口语化英文""口语化对白版" |

**B 口径下，英文不再逐字复刻源稿对译**，台账须写成「中文锚句 → 口语版英文 → 原文对照」三段式（原文对照仅存证，不参与判定）。
漏判此分支会把合规稿误报为 FAIL。同理：正文 ⑩ 行内不得残留中文台词；⑨ 字段里若引用了台词（如「我怕你死掉」），也要同步改为口语版英文片段。

## 改稿版本迭代（vN → vN+1 的派生核查）

改稿不要整篇重写，**从上一版 docx 只读派生**（原版保留不覆盖）：

1. 构建脚本 = 子串级替换规则表（`old → new`）＋ 正则规则（处理 md 侧 `**加粗**` 导致的子串不匹配）＋ 台账整段替换 ＋ 插入段（版本说明、新增自检项）。**子串级优于整段重写**——不依赖未截断的全段文本。
2. 段内替换优先 **run 级**（`for r in p.runs: if old in r.text: r.text = r.text.replace(...)`，保住格式），run 级未命中才整段重写（保留首 run 格式、删除其余 run）。
3. 逐镜字段定位靠「镜次标题行跟踪当前 SC」＋「`│` 后首字符圈号定字段号」，不要靠固定段索引。
4. 脚本必须**打印每条规则的命中次数（docx 与 md 两侧分别统计）**；零命中或两侧不一致即视为失败——本次实测至少一条规则会因 md 的 `**` 而单侧零命中。
5. 质检脚本对 **docx 与 md 双侧同检**，并核 v7→v8 的变更项（如"正文零服装命中 = 0"）与不变的铁律项（站位锚定 12/12、眨眼 12/12、字段 12×12）。
6. **字段级差异比对**是证明「某类字段零改动」的唯一硬手段：按**镜号 × 字段号**切分 vN 与 vN+1 的正文区，
   把不许动的字段（台词 ⑩／景别 ①／焦距 ③／运镜 ④／音效 ⑪／微表情 ⑨）**逐字比对**，
   其余字段输出差异清单并逐条说明。只说"整体没大改"等于没核；差异清单必须**恰好等于预期条数**才算 PASS。
7. **★ 改完文档必须回改上游构建脚本与同源 md，否则重跑即回退**：子串规则表的 `new` 侧一旦被判错并改正，
   构建脚本里仍是错的 ⇒ 下次跑 `build_*.py` 会把**已改正的错误原样写回**。
   实测（EP20 v9 座次改反）：需同步 **4 处脚本**（RULES 2 ＋ 插入块 A1 1 ＋ 版本说明 1）＋ **同源 md 6 处**，
   并在脚本内加**防回退注释**（写清正确口径 ＋ "勿回退"）。
   验证法＝**用修正后的脚本在临时目录重建一份 → 与落盘成品逐段比对「段落文本 ＋ 段落样式」**，
   二者**双零差异**才算脚本已恢复为单一真值源（比对前把脚本的 `DST_*` 指到 temp，别覆盖成品）。
8. **落到本地 Office 编辑通道做「就地修改」时，别把 `save_file` 当落盘判据**：`tencent-local-office-edit`
   的 editor_sdk **会自行落盘**——`get_pool_status` 的 `last_saved_ms` 与磁盘 mtime **毫秒级一致**（实测可对上）。
   且编辑器**重序列化后字节数会变**（实测 59841 → 48799），**字节数差不代表内容变化**。
   ⇒ 复查一律以**磁盘 mtime ＋ 内容**为准；判等只认「段落文本 ＋ 段落样式」逐段比对，不看文件大小。
   操作前先记 mtime/size 作基线；改后按 `doc_find` 全量扫描并对**该词族**（如"近端／远端"）逐条归类
   ——分清哪些是**人物座次**（须改）、哪些是**机位方位**（勿动）。

### 大改动量改稿 · 段落级重建法（v1.7.0 新增 · 改动镜数占比 > 约三成时改用）

当单次改动的镜数占比超过约三成（实测：EP17 v6→v7 为 17 镜中改写 8 镜 ＋ 新增 2 镜），**子串级替换会退化成脆弱实现**——正则规则数量爆炸、命中次数难以双侧对账、字段定位易错位。此时改用**模板克隆 ＋ body 重排**：

1. 解析源稿成镜块结构（`^SC\d\d- ` 切分，每镜 = 1 镜名 ＋ 1 `│` ＋ 12 字段）；解析后先断言「镜数 == 预期」「每镜字段数 == 12」，不通过立即中止。
2. 从源稿分别 deepcopy 一份样本段落作模板（H1／H2／H3／ListBullet 单 run／ListBullet 多 run／镜名 bold／`│` 行／字段行）——**样式、加粗、引用块底纹全部 100% 继承**，无需重建样式表。
3. 用 `Paragraph(deepcopy_p, parent)` 设文本；**多 run 条目**（如「关键词加粗 ＋ 正文」的条目）按 `[(text, bold), ...]` 分段填充，以保住关键词加粗观感——否则整条会被首 run 格式刷成通体加粗。
4. 清空 body 全部 `w:p` 后按新序列重排，`sectPr` 原样保留。
5. 无需改动的整段（如全局设定里未变的铁律条）**直接 `copy.deepcopy(src_paras[i]._p)`**，比重新生成更保真。

**两个必踩坑**：

| 坑 | 现象 | 正确写法 |
|---|---|---|
| `build()` 与 `save()` 不是同一个 Document 对象 | 先 `shutil.copy(SRC, DST)` 再 `doc = Document(DST)`，却在 `build()` 里改 `Document(SRC)` 的 body ⇒ **产物静默等于源稿**。更危险的是 QA 仍会「全绿」式的自欺（若 QA 读的是别的中间产物）或报出与预期完全一致的旧结构 | `build()` 改哪个对象，就 `save()` 哪个对象；改完直接 `src_doc.save(DST)`——python-docx **不会回写 SRC**，源稿天然安全。落盘后**必须重新解析 DST 核对段数与镜数**，不能只看脚本打印的段数 |
| 补丁文本只写字段正文、漏字段名 | patch 表里写「竖屏，凯安自画面右侧…」，产出变成 `│   ② 竖屏，凯安…`——**缺「画面构图：」**，且肉眼扫读极易放过 | 建 `字段号 → 字段名` 映射（2→画面构图／4→运镜／7→人物站位 + 朝向／8→肢体动作／9→微表情／11→音效／12→衔接…），由 `fldv(n, body)` 拼出 `│   ② 画面构图：…`；并加断言「每个字段行须以 `│   ①–⑫ 字段名：` 开头」 |

**配套 QA 新增三断言（本轮定型）**：

1. **字段行格式闸** —— 每行须匹配 `│   ①–⑫ 字段名：`，不匹配即 FAIL；
2. **旧口径残留闸** —— 上一版独有的陈旧数字/串（旧镜数、旧场次时长区间、旧发声单元计数等）须 `count == 0`；
3. **构图回归闸** —— 本轮新设定的禁写表述，在**指定的镜段区间**内 `count == 0`。

**★ 配套铁律（已在本技能 §判据陷阱确认，此处再次命中）**：正文里**禁止用「不出现 XX / 不得出现 XX」的否定式自述**来声明自己合规——它会照样被自己的禁词扫描抓出。一律改**正面描述**（把「画面中轴不出现空白」写成「画面重心全部收在右侧这道人物屏障上」）；自检章若需说明，也不得写出被禁旧词的全称。

### 质检脚本的定位陷阱（全部真实踩过）

| 陷阱 | 现象 | 正确写法 |
|---|---|---|
| 正文区起点用 `find('分镜正文')` / `rfind` | 「分镜正文」在 docx 里出现 3 次（标注口径句／Heading／自检章），`rfind` 落到自检章 ⇒ 正文区为空、逐镜检查静默跳过 | **起点固定用 `SC01- `，终点用台账标题**（如 `英文台词原文台账`） |
| 正文区终点用「中文片尾字幕」 | SC12 ⑩ 行含该串，正文被提前截断 ⇒ 末镜报"缺 ⑪⑫" | 终点改用台账标题 |
| 「」全量正则匹配台词 | 情绪节拍、新闻标题、强调词（如「距离一寸即张力」）被误判为中文台词 | 只扫含 `⑩` 且含 `台词` 的行 |
| md 自检结论行 startswith 串多写 `**` | md 里该行是 `**【机器化自检结论】✅`（**无收尾 `**`**），匹配失败 ⇒ 插入项缺失 | 用 `'**【机器化自检结论】'` |
| 中文锚句提取用 `split('｜')[0]` | 取到「旁白」「凯安（…）」等标签而非锚句 | 过滤掉以人物名/旁白开头的候选后取**最长**的一条 |

### 判据陷阱（v1.2 新增，全部真实踩过）

| 判据陷阱 | 现象 | 正确写法 |
|---|---|---|
| 禁词用**单词裸扫** | 「微光」在「平板微光」里是**设备光**、合法，却被判成人体自体发光 ⇒ 假阳性 | 禁词一律写**「人体部位＋发光」组合**：指尖发亮／指间微光／指缘发光／眼底亮起／自体发光／最亮的一点 |
| 在**自检条或版本说明里引用禁词全称** | 例如写「原『并肩迎战锁帧』已改为…」⇒ 该串被自己钉进文档，此后机器扫描**永久报残留**，越改越脏 | 自检条改用**中性指代**（"按 XX 铁律去除禁词、改用中性标签"），不写旧标签原文；若某处确属**源稿引用**（如「源稿依据」行的章节名），判据须**显式放行该行** |
| 预期差异条数只写在提示语里 | 实际允许变动 8 处、提示语写 7 处，多出的 1 处无人察觉 | 预期条数写成**常量并断言**，不等即 FAIL |
| 座位／方位类口径改了**却不加回归闸** | 座次写反后确实改正了，但 `_qa_*` 没断言"旧串归零" ⇒ 下次重跑构建脚本**静默写回**，无人发现 | 每处方位口径改动都配**两条断言**：旧串在 docx 与 md **双侧 `count == 0`**、新锚定串 **`count == N`**（N 为实测命中数） |

> **口诀：禁词的"提及"也算残留。** 想证明某个词已被清除，就不能在文档任何位置再写出它——包括自检章。

## 执行流程

### 步骤 1 · 抽取原剧本该集全文（建立比对基线）

先定位集数边界，**不要凭标题猜**。用 `scripts/extract_episode.py`：

```bash
<managed_python> scripts/extract_episode.py <剧本.docx> <集名关键词> <输出.txt>
```

它会打印所有集数标记行及段号，再导出目标集区间。**把导出文本贴在眼前，手工枚举全部"发声单元"**（含内心 OS、画外音、文字/语音消息），这份枚举就是第 1 轮的输入。

> 发声单元 ≠ 台词行。内心 OS、Q 版小人吐槽、手机消息文本都算，因为它们都要配音或都属"原剧本台词"保护范围。

### 步骤 2 · 填入 verify.py 的 `orig` 列表并跑核查

`scripts/verify.py` 顶部有 `ORIG` 列表（角色, 原句）。**每集只需替换这个列表和文件路径**，其余逻辑通用。

比对采用**去标点归一化子串包含**：
```python
norm = lambda s: re.sub(r"[^\u4e00-\u9fff0-9A-Za-z]", "", s)
ok = norm(原句) in norm(分镜全文)
```
这样可容忍分镜里改用不同引号（「」vs ""）、加了说话人前缀、插入四维标注，但**任何字词增删改都会立刻报错**。

### 步骤 3 · 跑 ledger.py 钉死台词计数

`verify.py` 只给总数，`ledger.py` 逐句列出「归属 + 四维有无 + 增添标注有无」。**必须人工过一遍这张表**，把每句归到三类之一：

- 原剧句（不得有〔增添台词〕标注）
- 增添句（**必须**有〔增添台词〕标注）
- 复用/回响句（原句在别处重复出现，不计入新增，但仍需四维）

三类数量之和必须等于脚本数出的「」总数。这个等式是本技能最有价值的一步——它抓出的错最多。

### 步骤 4 · 修正文档，让所有数字与脚本一致

改完再跑一遍 `verify.py`，直到全绿。**不要只改正文不改头部标记，也不要只改头部不改自检章**——三处数字必须同步。

### 步骤 5 · 转 docx 并校验

```bash
<managed_python> _md2docx_v2.py <in.md> <out.docx>
<managed_python> scripts/verify_docx.py <out.docx>
```

## 踩坑清单（真实发生过，务必逐条排查）

### 坑 1 · 集数错位（代价最大）
工作区已有的"第 N 集分镜"文件**可能用错了源集**（例如把原第二集改标成第三集）。
→ **动手前必须回原剧本 docx 用集名关键词定位段号区间**，不要信文件名、不要信已有草稿。
→ 发现错位时，明确在记忆里标注"某版作废勿引用"，否则下次还会踩。

### 坑 2 · 头部标记与正文数字漂移
"增添镜头四处"写在头部，正文却标了 6 个〔增添镜头〕；"增添 1 句"写在自检章，正文实际 4 句。
→ 增添项的**唯一真相源是正文标注**。头部与自检章的数字必须由脚本数出来后回填，禁止手写。

### 坑 3 · 镜号断号被"总数"掩盖
写到 SC35 后跳写 SC40，头部仍称"40 镜"——总数对得上，序列却断了。
→ 必查序列连续性，不只查总数。插入镜用 `SC13b` 形式，脚本要单独排除后再验连续。

### 坑 4 · 氛围修辞误触能力铁律
用户禁用某能力（如"时间暂停/时间冻结"）的新增使用场景，但分镜里写了"⑦ 氛围：时间凝固""⑧ 模特动作被冻结"——它们其实指人物受惊呆立的物理静止，与能力无关，可审片时必被误读为违规。
→ **逐镜正文（①–⑫ 字段）内直接禁用该能力的关键词**，改写为无歧义措辞：
  - "被冻结" → "硬生生刹住 / 顿在半途"
  - "时间凝固" → "死寂骤降、空气发紧"
  → 并就地加注"纯人物反应造成的静止，与外星能力无关"。
→ 关键词仅允许出现在【全局设定·能力铁律】与自检章的**否定性声明**中。

> **⚠ 硬标准（真实踩过）：加了"非"字的否定性注释，出现在逐镜正文内同样违规。**
> 实际案例：为自证清白，在镜头字段里写 `⑥ 氛围：外星被动能力的可视化（非时间冻结）`、 `⑪ 音效：超视距能力音效，非时间冻结`——本意是否定，但关键词已落在 ①–⑫ 正文字段内，审片检索时照样命中，等于自己制造违规证据。
> **正确做法**：逐镜正文内彻底删掉该词（改为"超视距凝视，纯旁观、不干预""超视距能力音效"等无歧义措辞），把"未发动时间冻结"这类声明放到全局设定与自检章去说。
> 判定口诀：**否定 ≠ 合规，位置才决定合规。** 只允许在全局设定 / 自检章出现，正文一个字都不能有。
>
> 另注：第 5 轮脚本会连带列出自检章的否定性声明（属允许范围），人工复核时**只盯逐镜 ①–⑫ 字段**是否命中即可，不要被自检章的命中数吓到。

### 坑 5 · 内心 OS 漏配四维 / 漏标增添
括号里顺手写的 `（甜内心OS：千万别被发现！不出声）` 既没「」也没四维，脚本按"无台词"跳过，人工也看不见。
→ 所有发声单元一律用「」包裹并配四维，"不出声"只是表演说明（写成"不出声、口型不动"），不构成免除配音标注的理由。

### 坑 6 · md→docx 残留 `**` 星号
旧转换脚本不解析行内加粗，Word 里出现一堆 `**`。
→ 用支持行内加粗解析的转换脚本；成品必须跑 `verify_docx.py` 断言 `txt.count("**") == 0`。

### 坑 7 · 分场归属与镜号区间不符
"第 2 场（SC15–SC24）"但正文第 3 场标题从 SC26 起，SC25 无场归属。
→ 分场区间必须由正文场标题顺序推导，并回到原剧本确认该镜发生在哪个场景（如 Q 版内心戏发生在帐篷内 → 属第 2 场，不属帐篷外的第 3 场）。

## 与体系内其他技能的边界

- 本技能**不写分镜**，只做交付前质检与格式转换。分镜创作归 `deepwhite-shotlist-builder` / `ai-manhua-director-thinking`。
- 配音四维的**标注规范**归 `ai-manhua-screenplay-comprehensive`；本技能只验证"有没有缺"。
- 微表情四维的**书写顺序规范**归 `micro-expression-annotation-system`；本技能只做顺序抽查。
- 提示词检索归 `ai-manhua-prompt-library`。

## 输出到文档的自检章写法

每轮结论必须带**可复核的数字或依据**，禁止只写"核查通过"：

> 第一轮自检（台词逐句核对 · 机器比对）：以"去标点后子串包含"方式，将原剧本第 N 集全部 **22 处发声单元**逐条比对正文，**缺失或篡改 0 条**。新增发声 4 句均标注〔增添台词〕；正文 ⑩ 字段「」标记合计 27 处 ＝ 原剧 22 ＋ 增添 4 ＋ 回响复用 1。核查通过。

结尾给一行汇总断言，把所有关键数字并列，便于一眼复核。

## 停止条件与不适用（2026-09-27 增补）
- **停止**：`verify.py` / `verify_docx.py` 全绿 + 各轮自检数字断言齐全 → 即交付，不再追加轮次；验收后的问题一律走新一轮「按镜迭代」，不在同轮热修。
- **停止边界**：机器全绿即放行——校验清单之外的审美判断（构图优劣、情绪到位与否）不在本闸门裁决范围，交还人工。
- **不适用**：非分镜类文档（剧本正本、提示词库、剪映草稿）不进本闸门；已交付旧稿按 2026-09-24 裁定**不追改**，不回流复检。
- **回归防线**：改动本技能或 verify 脚本后，必须先跑 `regression/run_regression.py` 全绿再放行（失败案例库，防校验规则被自己改坏）。
